FAULT TESTS — 1,000 node processes on 30 machines
================================================================================
Claim      : the final process-kill/restart and host packet-drop tests passed
             their gates. In the final impostor-identity test, node 0 rejected
             the forged handshake response; after healing, that run also passed.
Machines   : 30 c7gd.8xlarge instances, ten in each AWS region. The passing
             impostor-identity test used a replacement fleet of the same size.
Fleet      : 1,000 node processes across us-east-1, eu-west-1 and ap-southeast-2,
             split 333/333/334; mTLS mesh and per-node WAL persistence.
Workload   : one writer injected 10,000 keys into node 0 in ten chunks of at most
             1,000 keys; inject_parallel=1. This was not a multi-writer test.
Settings   : 256 MiB arenas, digest wait 1500ms, and a 600 s gate bound.
Date       : 2026-11-06; all timestamps below are UTC.
Clock      : converged_at_ms is measured after origin quiescence, not from the
             start of injection. Timestamp-derived elapsed times are shown too.
--------------------------------------------------------------------------------
Command and measurement

The retained driver expanded to the following gate invocation for each test.
The executable uses its public name; bracketed tokens replace private paths.
Options and values are unchanged. The multi-machine driver is not published.

  fleet-gate -bootstrap [fleet-bootstrap] -split 333,333,334 -keys 10000 \
    -inject-parallel 1 -slo-secs 600 -require-n 1000 -inject-chunk 1000 \
    -deck [configuration-file]

The fault hooks ran in addition to this gate. Their actions and second-resolution
timestamps come from the fault records; the hooks are not published as runnable
reproduction scripts. The consoles do not capture full node argv. The companion
convergence receipt lists the configuration-file and launcher settings.

Quiescence requires a stable seed root and commit_in_flight==0 across 12
consecutive polls, with a 250 ms sleep between polls. The gate then polls the
other 999 roots. A convergence time is when a poll observed equality, not the
exact instant the last node changed.

Elapsed times below are differences between raw timestamps, not sums of the
separately rounded phase durations.

Process kill and restart — attempt-038

At 12:17:13Z, after injection had begun, the hook ran kill -9 against the PID
file for node 333 on its eu-west-1 host. No other node was targeted. The note
says "holding 15s (> 10s write-deadline) before relaunch". At 12:17:30Z the
relaunch record specifies node 333, k=0 and mesh port 7373.

The requested hold was therefore 15 seconds, while the two logged command
timestamps are 17 seconds apart. Both facts are retained; neither is presented
as a more precise downtime measurement.

The gate recorded PASS, converged_at_ms=15716, a common Merkle root, and one
common state fingerprint across all 1,000 nodes. Per-region t100_ms values were

command applied an iptables DROP rule for TCP port 7373 with a requested hold

7373. At 12:20:53Z, the hook removed the rule.

31 seconds apart. The receipt retains both the configured duration and the

Impostor-identity test — attempt-039

This was a pre-gate test involving node 0 as victim and node 333 as gateway.
At 12:37:53Z, a host firewall rule isolated node 0 from the gateway's address.
At 12:37:54Z, node 0 was relaunched with k=0 and mesh port 7373.

At 12:38:02Z, the impostor established TLS to node 0 on port 7373 while
presenting the leaf certificate named X in the raw record. The certificate's
recorded source path identifies it as node 333's certificate. The impostor
received 57 bytes, then sent a forged 133-byte SGWC challengeRoleResponse.
Node 0 logged "signature verify FAILED count=1"; remoteVerified stayed false,
and the fault record reports "0 data-plane hijack". The run summary likewise
records sig_fail_lines=1.

At 12:38:03Z, before injection began, the isolation rule was removed. The gate
then recorded PASS, converged_at_ms=6221, a common Merkle root, and one common
state fingerprint across all 1,000 nodes. Per-region t100_ms values were 221 in
us-east-1, 6,221 in eu-west-1, and 2,799 in ap-southeast-2.

First attempt and replacement-fleet repetition

Attempt-040 started at 12:22:07Z and ended at 12:24:11Z with RUN_RC=4. It has
no recorded gate verdict and no convergence time. The record does not establish
the cause of that exit code, and this attempt is not counted as a pass.

After the first fleet was terminated, replacement-fleet launch began at
12:29:58Z. All 30 stopped instances were capacity-refused and replaced. The
new attempt started at 12:37:16Z and completed with PASS and RUN_RC=0 at
12:39:25Z; its console and bundle are the attempt-039 evidence above. This was
a separate fleet, not a retry on the same machines. The capacity refusals were
recorded during the later restart and are not a recorded cause of RUN_RC=4.

--------------------------------------------------------------------------------
Merkle roots, state fingerprints, and xor_root

The common Merkle roots above come from the gate's /v1/merkle polls. A Merkle
root is a root over dots. The state fingerprint comes from
/debug/state-fingerprint and also covers the associated state. The U1_SUMMARY
lines give the full common state_fp values and record 1,000 rows, 10,000 keys
on every row, unique_fps=1, and fp_all_equal=true for each test.

xor_root is a different, per-node field in the raw harvest tables. The retained
harvest takes the last root= value in each node's log, with the node ID as a
fallback when no such value is found. It is not the common Merkle root and is
not the fleet equality check. Values can therefore differ between nodes even
when all Merkle roots and state fingerprints are equal.

In the impostor-identity table, node 333 has xor_root
3ea96b4954bef220e6750e75639ab36f and node 0 has
5e669e91fae71bcd7d53e681a23e1a8c. Those are respectively the responder and
challenger values in the forged response quoted above. This is a correspondence
between the raw records, not an assertion that xor_root is a Merkle root.
