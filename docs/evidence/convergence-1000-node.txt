MULTI-REGION CONVERGENCE — 1,000 node processes on 30 machines
================================================================================
Claim      : three consecutive runs converged after origin quiescence in 2.906 s,
             4.038 s and 3.823 s. All 1,000 nodes had the same Merkle root, and
             all 1,000 state fingerprints within each run were equal.
Machines   : 30 c7gd.8xlarge instances, ten in each AWS region.
Fleet      : 1,000 node processes across us-east-1, eu-west-1 and ap-southeast-2,
             split 333/333/334; mTLS mesh and per-node WAL persistence.
Workload   : one writer injected 10,000 keys into node 0 in ten chunks of at most
             1,000 keys; inject_parallel=1. This was not a multi-writer test.
Date       : 2026-11-06; timestamps below are UTC.
Binary     : SHA-256 1ea150075c3476ed33c2e7e7ff78b85586bd6c1f94c41366345eef0aaf958b76

--------------------------------------------------------------------------------
Fleet derivation

The preparation register has 30 placement rows. The first ten are us-east-1,
the next ten are eu-west-1, and the final ten are ap-southeast-2. Each region
therefore has ten machines. The bootstrap record specifies the 333,333,334
process split.

In us-east-1 and eu-west-1, three machines carry 34 processes and seven carry
33: 3*34 + 7*33 = 333. In ap-southeast-2, four machines carry 34 and six carry
33: 4*34 + 6*33 = 334. These counts come from the placement slices, not from
assuming an even processes-per-machine layout.

Gate command

The retained driver expanded to the following gate invocation. The executable
uses its public name; bracketed tokens replace private paths. Options and values
are unchanged. The multi-machine driver itself is not published.

  fleet-gate -bootstrap [fleet-bootstrap] -split 333,333,334 -keys 10000 \
    -inject-parallel 1 -slo-secs 600 -require-n 1000 -inject-chunk 1000 \
    -deck [configuration-file]

The driver set ARENA_MIB=256 and digest wait 1500ms. The gate used its built-in
defaults for the control and metrics port bases, a 300 s quiescence cap, a 180 s
liveness retry window, and the enabled fingerprint sweep.

Clocks and polling

Injection time is the timestamp printed immediately before the batch writes.
Quiescence requires a stable seed root and commit_in_flight==0 across 12
consecutive polls, with a 250 ms sleep between polls. The post-quiescence gate
then reads the seed root and scrapes every non-seed root concurrently, sleeping
200 ms after each incomplete round. A reported convergence time is when a poll
observed equality, not the exact instant the last node changed.

Each injection-to-convergence value is the convergence timestamp minus the
injection timestamp in its row. Each post-quiescence value is the convergence
timestamp minus the quiescence timestamp. These are timestamp differences, not
sums of separately rounded injection, quiescence and convergence durations.

Node configuration

This list comes from the retained configuration file and launcher. The launcher
appends the configuration flags after its fallback flags, so the last occurrence
wins. The raw consoles do not capture full node argv; they are not direct argv
evidence.

Non-default convergence and topology settings:

  --region-aware                         (default off)
  --self-region 1, 2 or 3                (default 0)
  --stratified-anti-entropy              (default off)
  --digest-wait-timeout 1500ms           (default 500ms)
  --defer-handler                        (default off)
  --sweep-phase-jitter                   (default off)
  --lamport-absolute-slack 15000         (default 1000)
  --partial-intra-view                   (default off)
  --defer-crossover                      (default off)
  --digest-wait-adaptive                 (default off)
  --gateways-per-region 3                (default 0)
  --iblt-v2                              (default off)
  --iblt-v2-min-buckets 21845            (default 0, which uses 1024)
  --arena-mib 256                        (default 64)

The 21,845-bucket floor was sized for this 10,000-key workload: 2.1845 buckets
per possible difference. The launcher's fallback mesh-write-timeout=0s was
overridden by the configuration file's 10s value.

The following were explicit defaults, not configuration changes:

  --region-fanout 3        --batch-size 100        --mesh-write-timeout 10s

Placement and persistence settings also differed from the single-node defaults.
For per-instance local index k, the launcher used --bind 0.0.0.0:7373+k,
--metrics-addr 0.0.0.0:9100+k and --control-addr 0.0.0.0:8443+k. The mesh
default is 127.0.0.1:7430; the metrics default is 127.0.0.1:7431; the control
listener is disabled by default. It supplied
per-node --node-id and --identity-seed values, --tls-cert, --tls-key and
--tls-ca paths, --peer-dir and --peers, and per-node --lsm-root and --wal-path
values. Identity seeds, key material, addresses and private paths are not
reproduced.

For measurement, the launcher also set SOVEREIGN_STATE_FP_DEBUG=1,
SOVEREIGN_RESPOND_INDEG_DEBUG=1, SOVEREIGN_MISS_LOG_CAP=10000,
SOVEREIGN_DIGEST_LATENCY_DEBUG=1 and SOVEREIGN_EXCH_DEBUG=1.
