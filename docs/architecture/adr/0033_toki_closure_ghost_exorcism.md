# ADR-0033: The TOKI closure — deleting `internal/temporal_store/` and rejecting the eager-lossy conflict resolver (won't-fix)

**Status:** Accepted (2026-08-11). A deletion-only change: it removes dead code plus three stale module dependencies, touches no core file, and changes no production path.

**Decision:** `internal/temporal_store/` (10 files, 1,576 lines including the 21-line README; 1,555 lines of `.go`) is deleted as zero-importer dead code — `rg "hr18vk/sovereign/internal/temporal_store"` returns zero hits (exit 1). The `go.temporal.io/sdk` (go.mod:25), `go.temporal.io/api` (go.mod:75), and `github.com/gogo/protobuf` (go.mod:54) dependencies are dropped from go.mod with a surgical three-line hand edit — not `go mod tidy`, and `uuid` at go.mod:15 stays a direct dependency. The planned "TOKI Conflict Resolution Integration" item is closed as won't-fix — a close-by-rejection, not a close-by-implementation: wiring TOKI's eager `Resolve` into `Join` would be a CRDT convergence-law regression (§2, M2), the live HAMT read path shipped in ADR-0032 already is the genuine lossless conflict resolution (M4), and the `go.temporal.io/sdk` orchestration was an external engine for a compaction job the in-process `L1Compactor` already performs (M3).

## §1. Context

The original design doc listed a "TOKI Conflict Resolution Integration" item: wire `internal/temporal_store/toki.go`'s `LWWOperator.Resolve` (a pure algebraic winner/loser pick, `toki.go:193`) into the engine's conflict path. The package was early scaffolding: `toki.go` (the `TOKI` interface plus `LWWOperator`), `ceiling.go` (a ring-buffer ceiling), `compactor.go` and `workflow.go` (a `go.temporal.io/sdk` workflow plus activity orchestrating "Zero-GC LSM L0→L1 Compaction"), and its test files. An earlier pass had already removed the `pkg/conflict/strategy.go` seam as zero-importer dead code; TOKI was never wired either, and the design-doc item stayed open. ADR-0032 then shipped the live HAMT read path (`engineHAMTAdapter` → `engine.State().Get`), which is the lossless conflict resolution the query layer (`selectLatestDot`, `pkg/mesh/gossip.go:228`, called by `handleGet` at `control.go:357`) already applies at read time. With that, the package and the design-doc item became load-bearing-obsolete: the resolution they would have provided is already shipped losslessly, and wiring the eager-lossy variant would regress the CRDT convergence law. This change removes the dead code and closes the item as won't-fix.

## §2. Root cause (one sentence) + the byte-verified constraints (measured before code)

**Root cause (one sentence):** the TOKI package was early scaffolding for an eager-lossy conflict-resolution path (`LWWOperator.Resolve` drops the loser) that the engine never adopted — the convergence law (`Join` is merge-union on `CausalDot`, `crdt.go:1089`, the core file) and the read-time LWW (`selectLatestDot`, lossless — the loser stays in the data path) already resolve conflicts losslessly, so the package was zero-importer dead code whose only effect was holding three stale go.mod entries plus 1,576 lines of source never exercised against production; the fix is to delete the package, drop the dependencies, and mark the design-doc item won't-fix.

- **§0.a — zero importers (the load-bearing safety check).** `rg -n "hr18vk/sovereign/internal/temporal_store" --glob '*.go'` returns zero hits (exit 1). No production package — not `cmd/sovereign-node`, not `internal/database`, not `pkg/sync`, not `pkg/mesh`, not `pkg/durability` — imports the package. The check passes: the deletion is build-safe, proven in advance on a throwaway copy of the tree (`rm -rf internal/temporal_store/` + `go mod tidy` + `go build ./...` exit 0; `go mod why` returns "main module does not need" for all three deps; `go list -m all | grep temporal|gogo` returns empty). The live-tree edit is the surgical three-line go.mod hand edit, not `go mod tidy`: my standing policy is to keep `uuid` direct at go.mod:15 so the live diff stays minimal — tidy would demote uuid to `// indirect` and shuffle about six lines.
- **§0.b — `Join` is merge-union (the convergence law, M2).** `DeltaCRDTEngine.Join` (`crdt.go:1089` — the core merge law, byte-identical since the first commit) runs `perShardMerge` (`:1221`), a per-entity dot-merge: every incoming `CausalDot` is inserted into the HAMT keyed by `HashCausalDot(dot, digest)` (`:1580`); no dot is dropped. This is the CRDT convergence law: a CRDT is a merge-union semilattice — `Join(a, b) = a ∪ b` (modulo causal-dot identity), monotone, idempotent, commutative. Wiring `LWWOperator.Resolve` into `Join` would violate the law: `Resolve` (`toki.go:193`) returns `(winner, loser, audit)` and the caller drops the loser (the `AuditRecord` carries `loser_tx_time` — the dropped event). A dropped dot cannot be re-merged on a foreign `AdvanceLamportTo` (the WAL-replay seed discipline, `recovery.go:78`, `firstMutation.Counter - 1`), so the CRDT would not converge across a crash-recovery gap — data corruption. The eager-lossy path is a convergence-law regression, not an optimization.
- **§0.c — the read-time LWW is lossless (M4).** `selectLatestDot` (`pkg/mesh/gossip.go:228`) picks the max-`SystemTime` entry from `engine.State().Get(key)` (`control.go:356`, the full dot set, `hamt.go:170`) — the same read path the `engineHAMTAdapter` (`main.go:1303`) uses. It is LWW at read time: it picks the winner for the response, but the loser stays in the HAMT — the data path is append-only (`grep Prune|Reset|Retire` over `crdt.go` is empty). The resolution is lossless: no dot is dropped from the data path, and a future query at a different txTime can pick a different winner. The eager `Resolve` duplicates this decision lossily (it drops the loser eagerly); wiring it would replace a lossless read-time pick with a lossy eager drop — a strict regression. ADR-0032's live HAMT read path is the genuine conflict resolution the design-doc item was reaching for; the package was obsolete the moment that landed.
- **§0.d — `go.temporal.io/sdk` was an external engine for our compaction (M3).** `workflow.go` (`CompactionOrchestratorWorkflow`, `workflow.go:10`) and `compactor.go` (`L0CompactionActivity`, `compactor.go:207`) used `go.temporal.io/sdk`'s `workflow` and `activity` packages to orchestrate "Zero-GC LSM L0→L1 Compaction" — an external durable-workflow engine for a job the in-process `internal/database/l1_compactor.go` `L1Compactor.Compaction` already performs (the background scheduler in `cmd/sovereign-node`). The Temporal orchestration was never wired (zero importers, §0.a); it was scaffolding for a compaction model the engine superseded in-process. Dropping `go.temporal.io/sdk`, `go.temporal.io/api`, and `github.com/gogo/protobuf` (a transitive Temporal dep) removes three stale go.mod lines for an orchestration engine the engine does not use.
- **§0.e — `gogo/protobuf` is a transitive Temporal dep (the honest dep chain).** `github.com/gogo/protobuf` (go.mod:54, `// indirect`) was pulled by `go.temporal.io/sdk` as the Temporal wire codec. With Temporal gone, `go mod why github.com/gogo/protobuf` returns "main module does not need" (proven on the throwaway copy). The dep is not used by any engine code — the engine's wire codec is capnp (`api/capnp/`, a core file), not protobuf. Dropping it is the honest closure of the dep chain.
- **§0.f — `uuid` stays direct (M5).** `go mod why github.com/google/uuid` returns a non-trivial chain (`cmd/sovereign-node` → `go.opentelemetry.io/otel/sdk/resource` → `github.com/google/uuid`) — uuid is still needed by the OTel resource SDK and the node's identity minting. My policy: keep uuid direct at go.mod:15 rather than let a `go mod tidy` demote it to `// indirect` and shuffle about six lines; the surgical three-line hand edit keeps the diff to exactly the three dropped deps. Verified: the post-edit go.mod diff is exactly three deletions, uuid stays direct at line 15, line count 92 → 89.

## §3. The mechanism design (decided before code)

- **EDIT A — `git rm -r internal/temporal_store/` (10 files, 1,576 lines).** The package is zero-importer dead code (§0.a) and the deletion is build-safe (proven on the throwaway copy). The four test files (`toki_test.go`, `toki_hostile_test.go`, `compactor_test.go`, `ceiling_test.go`) tested the package in isolation via a `go.temporal.io/sdk/testsuite` mock (`compactor_test.go:11`) — not against the production engine. Their deletion removes ~582 lines of test code that tested nothing the engine ships.
- **EDIT B — the surgical go.mod hand edit (three deletions).** Delete exactly: `go.temporal.io/sdk v1.45.0` (go.mod:25, the direct block), `github.com/gogo/protobuf v1.3.2 // indirect` (go.mod:54, the indirect block), `go.temporal.io/api v1.62.12 // indirect` (go.mod:75, the indirect block). uuid (go.mod:15) stays direct. No `go mod tidy`. The three deletions are the only go.mod change (verified: `git diff go.mod` shows exactly three `-` lines, no shuffles).
- **EDIT C — `go.sum` is not hand-edited.** `go.sum` is regenerated by the build (`go build ./...` rewrites the checksum cache for the deps still in the graph), and the three dropped deps' checksum lines fall out naturally on the next build. If the build does not rewrite `go.sum`, the stale checksum lines are harmless — `go build` ignores checksums for modules not in the build graph, and a future `go mod tidy` cleans them. The live diff is go.mod plus the deletion only.
- **EDIT D — the architecture notes.** The engine-state table row for the TOKI conflict resolver flips from "exists, unwired" to "deleted (won't-fix — Join is a core merge-union; the live HAMT read path is the genuine conflict resolution)", and the earlier `pkg/conflict/strategy.go` deletion note gains an appendix recording that the `internal/temporal_store/` package is now gone for the same reason — the same zero-importer dead-code class, the same convergence-law argument.
- **EDIT E — this ADR and the ADR index entry.** The won't-fix record is this document.

**REFUTED (not shipped):** the alternative "wire `Resolve` into `Join` as an opt-in strategy" — the design-doc item's literal ask. Refuted on §0.b: `Join` is locked by the single-writer root-equality constraint, and even if it were not, wiring a lossy eager drop into a merge-union semilattice is a convergence-law regression (a dropped dot cannot re-merge across a foreign `AdvanceLamportTo`). The lossless read-time `selectLatestDot` (§0.c) already resolves conflicts; the eager-lossy variant is a strict regression. The item is won't-fix, not deferred.
