## §2. The root cause (one sentence) + the four byte-verified constraints

## §3. The mechanism design + the equivalence proof (decided BEFORE code, per §1)

**Mechanism chosen: B — the ACTIVE-DOMINATOR-SET SWEEP with a brute-probe containment** (the ADR-0020 §6(b) named "interval-tree / segment-sweep"; the prompt's recommended path — lowest allocation, natural per-entity batch, one-line survivor-set invariant). The sweep is local to the `DominancePrune` body + an unexported `liveInterval` helper struct (16 bytes, 0 pointer bytes — fieldalignment-clean; NO new exported type).

**The sweep.** Given the production-precondition sysTime-ASC `rows`:
1. Walk the rows in REVERSE by EQUAL-sysT batches. Batching equal-sysT rows preserves (C1)'s strict inequality — two rows at the same sysTime cannot dominate each other (`sysTime(R') > sysTime(R)` is strict), so a batch is probed against ONLY the already-processed strictly-newer batches.
2. Maintain `live` = the set of ADMISSIBLE dominator intervals from the strictly-newer, floor-admitted rows that survived their own probe. Each entry carries ONLY `(vs, ve)` (the containment-claw fields; (C1)+(C3) are enforced by the sweep order + the admission guard, so the probe checks containment ALONE).
3. For each row R in a batch: probe `live` for a CONTAINER of `[vs_R, ve_R)` (C2). FOUND → R is dominated (mark). NOT found → R survives.
4. After probing, admit the batch's SURVIVORS with `sysT <= horizon` into `live` (the (C3) floor gate — a row with `sysT > horizon` is NEVER admitted; it can never be a SAFE dominator for an older row). Non-floor-admitted batches are silently skipped.
5. Forward-compact the non-dominated rows into a sub-sequence (preserve input order — byte-identical to the reference's in-place sink compaction).

**The (C3) floor mechanics (the §1.1 subtlety).** The admissible live set at row R (batch sysT = T) is `{rows seen so far with sysTime > T AND sysTime <= horizon}` — exactly the rows a forward full-rescan would test, restricted to those PASSING (C1) (newer) and (C3) (floor-admitted). A row with `sysTime > horizon` is NEVER admitted (it fails (C3)); once the sweep passes `horizon` (the current batch sysT <= horizon), all surviving strictly-newer rows ARE floor-admitted. The (C3) floor is the hard part — a naive "newest dominates" sweep is the φ-break the T1 RED control catches.

**The EQUIVALENCE PROOF (R dropped by the O(N²) reference IFF R dropped by the sweep — the byte-identical-survivors guarantee).**

Let `D_ref = {R : ∃ R' in rows with sysTime(R') > sysTime(R) ∧ sysTime(R') <= horizon ∧ [vs',ve') ⊇ [vs,ve)}` (the reference's dominated set — a full O(N²) scan over ALL rows, survivors AND dominated).

**(forward) `D_ref ⊆ D_sweep`:** Suppose R ∈ D_ref — R is dominated by some R'. If R' survived its batch's probe (it was not itself dominated by a strictly-newer row), then R' is in `live` when R's batch is processed → the sweep's probe finds R' (a container of R) → R ∈ D_sweep. If R' was DOMINATED (the reference also drops R'), then R' was NOT appended to `live`; but R' ∈ D_ref means ∃ R'' dominating R' (the chain R ← R' ← R''...). The chain STRICTLY RISES in sysTime (each link is (C1) newer) AND stays ≤ horizon (each link is (C3) floor-admitted) AND containment is TRANSITIVE (C2: [vs_a,ve_a) ⊆ [vs_b,ve_b) ⊆ [vs_c,ve_c) → ⊆). sysTime is a finite strictly-increasing integer bounded above by `horizon`, so the chain TERMINATES at a survivor S* that is in `live` (it survived its probe by definition of termination) with S* ⊇ … ⊇ R' ⊇ R. So S* is a container of R in `live` → the sweep's probe finds S* → R ∈ D_sweep. ∴ D_ref ⊆ D_sweep.

**(reverse) `D_sweep ⊆ D_ref`:** The sweep drops R iff its probe found an admissible S in `live` with S ⊇ `[vs_R, ve_R)`. By construction, S is: (a) strictly newer than R (C1 — `live` only holds rows from strictly-newer batches), (b) floor-admitted (C3 — the admission guard `batchSys <= horizon`), (c) a container of R (C2). So S is a dominator of R in the reference's sense → R ∈ D_ref. ∴ D_sweep ⊆ D_ref.

∴ **D_sweep = D_ref** — byte-identical dominated sets → byte-identical survivors. The forward compaction preserves the input order, so the survivor SEQUENCE is byte-identical to the reference's in-place sink compaction (the column-append loop reads identical bytes). The T-EQUIV fuzz tooth (≥10,000 cases) GATES this empirically; the proof is WHY it holds.

## §8. Self-adversarial (the §8 discipline — fight the proof)

**Adversary 1 — the transitivity chain might be INFINITE.** The forward direction of the equivalence proof chases R ← R' ← R'' …. Could the chain NOT terminate (a cycle)? **No**: each link STRICTLY RAISES sysTime (C1 `sysTime(S_) > sysTime(S_{-1})` — strictly-greater, not ≥). sysTime is an int64 bounded above by `horizon` (C3 — every link is floor-admitted, so sysTime ≤ horizon). A strictly-ascending sequence of integers bounded above is FINITE → the chain terminates at a survivor (a row not dominated by a strictly-newer floor-admitted row, i.e. the max-sysTime floor-admitted row OR a row no newer+superset+floor-admitted row contains). ∴ the proof holds. The T-EQUIV fuzz (10,000 cases, randomized N up to 2000) GATES this empirically — no non-termination surfaced.

**Adversary 2 — equal-sysTime batching might MISS a dominating row within the batch.** (C1) requires `sysTime(R') > sysTime(R)` STRICTLY. Two rows at the SAME sysTime CANNOT dominate each other (the inequality is strict). So probing a batch against ITSELF is WRONG (would violate C1) — the batch is probed ONLY against the strictly-newer `live` set. The batching is C1-correct by construction. But could two same-sysTime rows with the SAME interval mutually dominate? NO — (C1) strictness forbids it; both survive (neither is newer). The T-EQUIV fuzz (randomized sysTime collisions across 0..500) exercises equal-sysTime batches heavily — no divergence surfaced.

**Adversary 3 — the (C3) admission gate is TOO narrow (a floor-admitted row in a LATER batch dominates a row in an EARLIER non-floor-admitted batch).** Consider R at sysT=100 (batch processed when `batchSys=100`), and a dominator R' at sysT=250 > horizon=200. R' is in a batch with `batchSys=250 > horizon=200` → the admission gate `250 <= 200` FAILS → R' is NOT admitted → R is NOT dropped. Is that CORRECT? **YES** — the reference would ALSO refuse: (C3) `sysTime(R') 250 > horizon 200 → continue` → R' is NOT a reference dominator either. The two agree (T1 byte-identical). The (C3) floor gate is the SAME in both. ∴ correct.

**Adversary 4 — the REVERSED input (T-REVERSED) might be a REGRESSION (the sweep gives a wrong answer on unsorted input).** The production contract is the sort at :520 RUNS before the prune. The sweep RELIES on sysTime-ASC; the reference is order-independent (a full double-loop). On UNSORTED input the two CAN diverge — BUT the prune NEVER sees unsorted input in production (the sort is the precondition gate). The T-REVERSED tooth DISCLOSES this honestly: it is NOT a regression (the production code never violates the precondition); it is the documented reliance. A sweep that RE-SORTED would be a STRICTER guarantee; the chosen sweep delegates to the production sort (the single minimum-blast-radius insertion point — re-sorting would be a restructure, anti-scope-creep). The disclosure is the honest answer — NOT a green-wash.

**Adversary 5 — the fuzz might not VERIFY the survivor ORDER (only the cardinality or the set).** The T-EQUIV tooth asserts `survivorsByteIdentical` — LENGTH + per-row frag[:] + ORDER (a forward index walk, not a re-sorted set comparison). A sweep that returned the right SET in the wrong ORDER would FAIL T-EQUIV (the column-append loop reads the survivors in order; an OOO output is a byte-different L1). The fuzz caught exactly this during development (the early fuzz used per-row distinct tags → frag[:16] differed → the production sort reduced to HASH order, not sysTime-ASC → the sweep's batch discipline broke → DIVERGENCE caught, root-caused to the fuzz violating the §0.b entity-field-CONSTANT precondition → fixed by using a constant tag 'x' → GREEN). The fuzz is load-bearing — it caught a real divergence + the corrected it. ∴ the byte-identity tooth is the ORDER check, NOT a set-identity check.

## §9. What this proves

The Level-3 prune refinement is a **correctness-preserving** algorithmic optimisation of a single pure function in an un-frozen file. The new O(N·H) active-dominator-set sweep returns **byte-identical survivors to the O(N²) reference on every input** — gated by a 10,000-case differential-equivalence fuzz (the strongest correctness gate a refactor can have) + the re-pinned T1/T2/T3/T4/T5/T6 claws. The sweep is **NEVER materially slower** than O(N²) (the worst-realized case is the accumulate case, ratio 0.50 — still 2× faster than the reference) and is **materially faster** on both the realized collapse (0.002) and accumulate (0.50) cases. The 5-file FROZEN set is byte-identical (the third clean-chain fork); the dead tombstone compactor stays dead; the AsOf/scanRecordBatch read path is UNCHANGED; the Preserve-All default is byte-identical to Day-14.

The honest headline is NOT an "X→Y" alloc frame (the prompt forbade inventing one). The engine never auto-prunes; the sweep preserves every survivor the reference did; trust is earned by the byte-identical survivors, not the O() adjective.
