# ADR-0032: The Read-Your-Writes Live δ-CRDT HAMT Seam — the LiveSource Interface + the AsOf/Range Live-Merge

**Status:** ACCEPTED (2026-08-10). This is a read-path + telemetry change; it does not touch the single-writer root-equality path, and no core file is modified.

**Closes:** the read-your-writes gap that the default checkpoint-interval behavior exposed (a new class, not a residual of an earlier decision). `Resolver.AsOf`/`.Range` read ONLY durable Arrow files; an entry a `POST /v1/insert` places in the live δ-CRDT HAMT (`engine.InsertLocal` CAS-spins the per-shard root, `crdt.go:983`) is INVISIBLE to `/v1/query` until the bridge's periodic `AppendCheckpoint` flushes `SnapshotToLSM` → L0 (`bridge.go:213`, gated by `checkpointInterval`, default 1000). With the default interval, every immediate `/v1/query` returned 404 — empirically confirmed: `--wal-checkpoint-interval=1` was required for the durable read path to work at all. This change closes the gap: the Resolver consults the LIVE HAMT after its durable Arrow scan and merges the live dominant under the SAME bitemporal dominance, so an insert is visible to `/v1/query` immediately, before any checkpoint. The live source is OPT-IN: a nil `LiveSource` keeps the durable-only behavior byte-identical to the prior behavior (the research-node default).

## §1. Context

The engine's read path (`Resolver.AsOf`, `query.go:381`; `Resolver.Range`, `query.go:730`) was durable-only: it lists L1 + L0 Arrow keys, downloads, scans, applies Filter2 (`sysTime <= txTime`) + Filter3 (the validTime window) + dominance (max `SystemTime` wins), and returns the dominant. The write path (`engine.InsertLocal`, `crdt.go:983`) CAS-spins the LIVE δ-CRDT HAMT's per-shard root — the entry is in the live HAMT immediately. The bridge (`pkg/durability/bridge.go:213`) periodically calls `AppendCheckpoint` → `SnapshotToLSM` (`snapshot.go:391`), which reads `engine.State().ForEach` and writes the L0 Arrow index. The two paths were joined only at the checkpoint boundary.

The gap: between an insert and the next checkpoint, the live HAMT holds the entry but the durable tier does not, so `/v1/query` 404s on a row the node just accepted. This is not a data-loss bug (the entry IS durable in the WAL — `pkg/durability` fsyncs per mutation); it is a read-visibility gap: the read path consults a stale projection of the live state. With the default checkpoint interval (1000 mutations) the gap is the common case, not the edge — the earlier harness required `--wal-checkpoint-interval=1` to make the durable read path work at all, which is the load-bearing empirical proof the gap is real. A database must not 404 a row it just acknowledged.

## §2. The root cause (one sentence) + the byte-verified constraints (measured before code)

**Root cause (one sentence):** the read path consulted the durable Arrow projection only (a periodic snapshot of the live HAMT), not the live HAMT itself, so an entry resident in the live HAMT but not yet checkpointed was invisible. The fix is a read-only consult of the live HAMT merged under the SAME bitemporal dominance the durable scan already computes — not a change to the write path, the checkpoint cadence, or the durable scan.

- **§0.a — the seam is an interface, not a concrete engine (load-bearing).** `internal/database` does not import `pkg/sync` (grep-verified; the import would close the `internal/` boundary the engine's layering depends on). So the live source cannot be a `*crdt.Engine` field on the `Resolver`. It is a `LiveSource` interface (`query.go:159`) owned by `internal/database`, implemented at the `cmd/sovereign-node` boundary where the concrete engine lives. This is the existing `SetResolver` injection precedent (`control.go` constructs the resolver, `main.go` injects it) carried to the live source — the same seam discipline.
- **§0.b — my first draft's SkipList-freeze premise was wrong.** The initial design proposed "freeze the live SkipList and read it directly via the `Seek` lower-bound." I rejected that on three grounds: (i) `Seek` is dormant by design (ADR-0028) — its only production consumer reads a frozen arena (`l0_flusher.go:198`), and wiring it into the live read path touches the write-path freeze/`Free` lifecycle, which is higher risk; (ii) the live MemTable is not a frozen SkipList — it is a per-shard CAS-spun HAMT (`crdt.go:983`), and a SkipList read would not see cross-shard entries (the entity's dots span shards); (iii) the read-your-writes contract is met by reading `engine.State().Get` (the full dot set, `hamt.go:170`), the same read API `handleGet` (`control.go:356`) and `SnapshotToLSM` (`snapshot.go:391`) already use — there is no need to freeze anything. The fix: a `LiveSource` interface whose `cmd/sovereign-node` adapter wraps `engine.State().Get` plus the EBR pin (the exact concurrent-read guard `SnapshotToLSM` uses, `snapshot.go:391-394`). The SkipList stays dormant; the HAMT read path stays.
- **§0.c — `live ⊇ durable`, always (the dedup premise).** The live HAMT is append-only, never pruned (grep `Prune|Reset|Retire` on `crdt.go`/`hamt.go` is empty; `AppendCheckpoint` → `SnapshotToLSM` only reads `engine.State().ForEach`, never mutates). The durable Arrow index is built FROM the live HAMT (`snapshot.go:436`). So after a checkpoint the live HAMT still holds the checkpointed dot AND the durable tier now holds the same row — a naive "append every live row" on `Range` would duplicate every checkpointed row, a correctness violation. The `Range` merge must dedup live against durable. The `AsOf` merge is dedup-free (a single dominant — max `SystemTime` wins; the live + durable dominants compete under the same `>`, and a live twin at the same sysTime does not displace the durable — the `>`, not `>=`, at `query.go:623`).
- **§0.d — the counter is the path disclosure, not the hit count.** `QueryLiveSourceReads` (`registry.go:144`, Prometheus `supremum.query.live_source_reads`, `registry.go:385`) fires ONCE per query that consulted the live path (`query.go:591`), not per live entry. A live read that returns zero entries still fires the counter (the path was taken; the live HAMT had no visible entry at `txTime`). This is the same disclosure convention the existing download-skip and manifest-skip counters carry — the count discloses the path, not the payload.
- **§0.e — the live source is opt-in (the back-compat contract).** A nil `LiveSource` (the `DefaultResolverConfig` value — a research node, `--lsm-root` absent, or `SetLiveSource(nil)`) keeps the durable-only behavior byte-identical to the prior behavior. The `:442` AsOf zero-durable early-exit and the `:775` Range zero-durable early-exit still fire (the `r.liveSource == nil` guard does not skip them); the live merge blocks (`:590`, `:890`) are not entered. The feature is opt-in via the live source, not a forced change to every resolver — `T-LIVE-OFF-IS-BYTE-IDENTICAL` is the load-bearing back-compat tooth.
- **§0.f — counter-count growth 17 → 18.** This change adds a new distinct counter (`QueryLiveSourceReads`), bringing the total to 18. The `Counters()` slice grows 17 → 18, and the existing counter-count assertions in the earlier tests are updated 17 → 18. The bridge surfaces the new series without a bridge edit (the bridge is byte-unchanged).

## §3. The mechanism design (decided before code)

- **EDIT 1 — the `LiveSource` interface (`internal/database/query.go:159`).** A plain interface: `LiveRead(ctx, entityID, txTimeNs) ([]LiveEvent, error)`. The impl must pin the live store for the call duration (the EBR `Acquire`/`Enter`/`Release` guard `SnapshotToLSM` uses, `snapshot.go:391-394`). `LiveEvent` (`query.go:124`) is a per-query DTO (not a contended atomic, so the 128-byte-stride cache concern does not apply), laid out fieldalignment-clean (the Payload slice + the 32-byte digest + the int64/uint64 scalars — the tool reports zero new findings; `internal/database` stays at 11). A nil `LiveSource` is the durable-only default.
- **EDIT 2 — the `Resolver` consult + merge.** `ResolverConfig.LiveSource` (`query.go:34`, declared first for fieldalignment) + `Resolver.liveSource` (`query.go:243`) + `SetLiveSource` (`query.go:338` — the `SetResolver` precedent: inject the live source after construction). AsOf: the `:442` zero-durable early-exit is guarded on `r.liveSource == nil` (skip it with a live source → fall through to the scan → the live merge at `:590` seeds the dominant); the merge applies the defensive Filter2 (`:610`, `le.SystemTime > txTimeNs` → `continue`) + Filter3 (`:615`, the half-open validTime window) + dominance (`:623`, the `>`, not `>=`). Range: the `:775` zero-durable early-exit is guarded on `r.liveSource == nil` (the same symmetry); the merge at `:890` dedups live against durable by `(SystemTime, PayloadDigest)` (`liveRowKey`, `query.go:1721`) before append.
- **EDIT 3 — the `engineHAMTAdapter` (`cmd/sovereign-node/main.go:1280`).** The `database.LiveSource` impl wrapping `engine.State().Get(entityID)` (`main.go:1303`, the full dot set, EBR-pinned by `a.engine.EBR().Acquire()` at `:1294`). Wired at `main.go:419` (`queryResolver.SetLiveSource(&engineHAMTAdapter{engine: engine})`) — the same seam the resolver itself is wired at. A research node (`--lsm-root` absent) keeps `queryResolver` nil → `SetLiveSource` is never called → durable-only (byte-identical to the prior behavior).
- **EDIT 4 — the new counter (`internal/telemetry/registry.go`).** `QueryLiveSourceReads` (`registry.go:144`, `newCounter` at `:384` + the `rebuildCounters` fill at `:549`) — Prometheus `supremum.query.live_source_reads`. Added to the `Counters()` slice at `:241` (the new distinct entry; the §0.f auto-surface). Incremented at `query.go:591` (AsOf) + the `Range` consult — once per live-path query, not per live entry.
- **Three refinements the initial prose hand-waved (disclosed here, not silently filled in):**
  - **M-ASOF-EARLY-EXIT** — AsOf has two early-exits (`:442` zero-durable, the `:425`-class dominant==nil) that fire before any "post-scan merge." My initial "merge after building the durable dominant" was structurally insufficient — the scan is inlined and the `:442` early-exit returns before it runs. The read-your-writes proof (insert → immediate query → 200, checkpoint disabled) requires the live path to rescue the zero-durable case, not just augment a successful scan. Fix: the `:442` early-exit is guarded on `r.liveSource == nil`.
  - **M-RANGE-DEDUP** — the initial "append every live row" (Range) would duplicate every checkpointed row (live ⊇ durable, §0.c). Fix: the `Range` merge dedups live against durable by `(SystemTime, PayloadDigest)` before append (the Arrow schema carries no dot columns, so dot-dedup is impossible at the row level; `(sysTime, 32-byte digest)` is the honest row identity — the digest is a content hash).
  - **M-DEFENSIVE-FILTER2** — my initial split was "the adapter applies Filter2; the Resolver applies Filter3 + dominance." A buggy or foreign adapter returning an entry with `SystemTime > txTimeNs` would — under trust-only — pass Filter3 + dominance and become the dominant → a silent correctness break (a row not visible at txTime). Fix: the Resolver defensively re-checks Filter2 (`:610`) — zero cost on a correct adapter (the check never fires) and a hard guarantee otherwise.

**Not shipped:** the initial "freeze the live SkipList and read it directly via `Seek`" mechanism. Rejected on §0.b(i)–(iii) — `Seek` stays dormant (ADR-0028), the live MemTable is a per-shard HAMT, not a frozen SkipList, and `engine.State().Get` already meets the contract without a freeze. The freeze would have been the higher-risk write-path change I had deferred; this change ships the read-only consult instead.

## §5. The teeth (the gate) — all green

- **`T-LIVE-OFF-IS-BYTE-IDENTICAL` (`internal/database`).** A nil `LiveSource` keeps the durable-only behavior byte-identical to the prior behavior — the `:442`/`:775` early-exits fire, the live merge is skipped. The load-bearing back-compat tooth. RED control: an entity with no durable data + a nil live source → the `:442` early-exit fires → `ErrEntityNotFound`.
- **`T-LIVE-MERGE-EQUIV` (`internal/database`, load-bearing).** The live + durable dominants compete under the same `>` (max `SystemTime` wins); a live twin at the same sysTime does not displace the durable (the `>`, not `>=`, at `:623`). The bug-inject flips `>` to `>=` and proves the boundary is load-bearing. The merged result is byte-identical to the durable-only result once the live entry is checkpointed into L0 — the live entry is the durable entry's seed (`SnapshotToLSM` writes the `CRDTEntry` verbatim, `snapshot.go:447`).
- **`T-LIVE-MERGE-EQUIV-RED` (`internal/database`).** The `>=` bug-inject catcher — the honest `>=` boundary divergence (a live entry at the durable sysTime displaces it under `>=`, not under `>`).
- **`T-LIVE-COUNTER-FIRES` (`internal/database`).** `QueryLiveSourceReads` fires once per live-path query, not per live entry. A live read returning zero entries still fires the counter (the path was taken).
- **`T-LIVE-RANGE` (`internal/database`).** The `Range` live merge appends the live window rows; the dedup removes the durable twins (M-RANGE-DEDUP). The bug-inject no-dedup catcher: remove the dedup → duplicates → the tooth catches it.
- **`T-LIVE-RANGE-EMPTY-DURABLE` (`internal/database`, load-bearing — the runtime-caught regression guard).** With no durable rows on disk + a live source, the `:775` Range early-exit is guarded on `r.liveSource == nil` (the guard does not fire) → the live merge at `:890` runs → the live window rows are returned → 200, not 404. This is the tooth runtime verification forced into existence: the first pass 404'd the immediate range (the `:775` guard was missing); the fix is the load-bearing symmetry. Bug-inject-proven (remove the `&& r.liveSource == nil` → the empty-durable Range 404s → the tooth catches it).
- **`T-LIVE-DEFENSIVE-FILTER2` (`internal/database`).** A buggy or foreign adapter returning an entry with `SystemTime > txTimeNs` is dropped by the Resolver's defensive Filter2 (`:610`) — the silent correctness break the trust-only design would have shipped.
- **`T-LIVE-NO-CORE-TOUCH` (`internal/database`).** The five core files are unchanged — this change touches no core file (the seam is an interface + a cmd-layer adapter, not a `crdt.go`/`crdt_apply.go`/`envelope.go`/capnp edit).

## §6. Future work (the honest deferred work, not this change)
