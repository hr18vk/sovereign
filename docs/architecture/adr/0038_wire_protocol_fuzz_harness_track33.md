## §1 — The Decision

SHIP a NEW test-tier package `pkg/security/fuzz/` — the native `go test -fuzz` harness against the FOUR-way `DispatchFrame` router (pkg/mesh/digest.go:176) + the FIVE ingest-path unmarshalers under it (`attribution.UnmarshalRelayEnvelope` / `UnmarshalBatchEnvelope` / `UnmarshalHybridFrame` + `sync.UnmarshalStrataEstimator` / `UnmarshalIBLT`). The harness asserts ONE property per input: the unmarshaler / DispatchFrame call RETURNS WITHOUT PANIC (the M3 oracle — the verdict VALUE is not asserted; the PROCESS STAYS ALIVE). The bug the fuzz catches is a PANIC: an out-of-bounds slice index, a nil-deref, an unbounded `make()` (OOM-kill), or an integer overflow that defeats a bounds guard. A native `go test -fuzz` does NOT recover — a panic FAILS the fuzz, which is the proof.

The harness is the trust anchor that makes the receiver's "NEVER panics on adversarial input" docstring contract (receiver.go:350 HandleFrame, :586 HandleBatchFrame, :823 HandleHybridFrame) a FALSIFIABLE BINARY instead of a prose claim. Day 29 (the digest frame) + Day 31 (the PQ-verify) + Day 32 (the hybrid SIGN frame) each ADDED a new magic + a new unmarshaler to that SAME dispatch surface WITHOUT a machine-driven adversarial input ever testing the claim — the proof-by-prose is now a four-arm-wide claim, each arm unaudited by a machine. Day 33 closes it.

**THE M1 frameSink REACHABILITY (the load-bearing correction the blueprint's Edit A did not anticipate).** `DispatchFrame` is EXPORTED, but its `recv frameSink` parameter's type is the UNEXPORTED interface `pkg/mesh/peer.go:174 frameSink`. A test in a DIFFERENT package (`pkg/security/fuzz`) CANNOT name `frameSink` in its source. Go's STRUCTURAL interface typing resolves this: a type that implements the three methods `HandleFrame` / `HandleBatchFrame` / `HandleHybridFrame` each taking a `[]byte` and returning a `receive.AcceptVerdict` SATISFIES `frameSink` without naming it, and a value of that type is assignment-compatible with the unexported `recv` parameter. `nopSink` (dispatch_fuzz_test.go) is that type. The conformance is proven at COMPILE TIME — the `mesh.DispatchFrame(..., nopSink{}, ...)` call compiles IFF `nopSink` satisfies the (unexported) `frameSink`; a future Day that edits `frameSink`'s method set breaks the compile here (the load-bearing reachability guard). `DigestSink` is EXPORTED (`DeliverDigest`), so `nopDigester` is a plain implementation. This is the load-bearing reachability fact — without it the dispatch fuzz could not live in `pkg/security/fuzz` (the blueprint's named home).

**THE M3 ORACLE (the load-bearing property).** Each fuzz target asserts the call RETURNS WITHOUT PANIC. It does NOT assert the returned `T` is semantically correct (that is the round-trip teeth's job — `TestEnvelope_MarshalRoundTrip` et al. already exist in `pkg/attribution`; this harness does NOT duplicate them). The fuzz is the ONLY enforcement of the no-panic contract — there is ZERO `recover()` / `defer func` in the production receive path (M2 — verified by grep; the one `recover` hit is in `envelope_test.go`, a test). NO recover guard is added to the production receive path (Law IV — a recover would MASK the crash this harness is chartered to surface; the fuzz is the ONLY enforcement, and a recover would defeat it).

**THE M4 SEED CORPUS (committed, NOT git-ignored — Law II reproducibility).** The `testdata/fuzz/FuzzX/*.txt` corpus dirs are TRACKED. The corpus is the M4 MINIMUM per target: (a) the valid magic + a well-formed body (the happy-path seed establishing each arm's coverage); (b) a TRUNCATED magic (the first 4 bytes + NO body — the length-bomb-empty shape); (c) a length-bomb (a valid magic + a uint32 length field of `0xFFFFFFFF` — the OOM shape); (d) a 1-byte and 0-byte input (the smallest adversarial shapes). **42 committed corpus seeds across 7 targets** (Dispatch 11 + Relay 6 + Batch 4 + Hybrid 4 + Strata 5 + IBLT 6 + BugInjectControl 6). The corpus files use the EXACT on-disk format `go test -fuzz` writes (`go test fuzz v1\n[]byte("...")` with `\xNN` escapes for binary bytes — generated via `strconv.Quote` for byte-faithful round-trip), so a corpus file this fork commits is byte-identical to what the fuzzer re-loads. The corpus is BYTE-FAITHFUL to the builders — enforced by `TestSeedCorpusMatchesBuilders` (T-FUZZ-CORPUS-BYTE-IDENTITY, added post-/ruthless-auditor; the §34 finding: the original `TestSeedCorpusIsValid` tooth enforced only no-panic, NOT the builder↔corpus byte-equality the §1 docstring claimed — the new tooth closes that enforcement gap, bug-inject-PROVEN to catch a real desync).

**THE BUG-INJECT CONTROL (T-FUZZ-BUG-INJECT-CONTROL — the Day-25 Law 5 / Day-31 T-PQ-KEM-CLASSICAL-CONTROL mold).** A fuzz that only feeds well-formed frames is a TAUTOLOGY; a fuzz that never catches an INJECTED panic is a no-op runner. The harness ships a deliberately-injected panic in a COPY of `UnmarshalIBLT` (a build-tagged `fuzzbuginject` target) where the bounds guard is DELETED, so on a short IBLT seed the loop reads past the wire's end → an out-of-bounds slice index panic (recoverable). The bug-injected unmarshaler copy is BUILD-TAGGED `fuzzbuginject` so it is ONLY compiled when the operator opts into the bug-inject proof — it can NEVER reach the production binary (the default build does NOT compile it; `go test ./pkg/security/fuzz/` stays GREEN).
