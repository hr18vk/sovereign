# ADR-0038: Wire-Protocol + CRDT-Apply Fuzz Harness — the Native `go test -fuzz` No-Panic Anchor for the 4-Way Dispatch + the 5 Ingest-Path Unmarshalers + the Committed Seed Corpus + the Bug-Inject Control

**Status:** ACCEPTED (2026-08-12) — a harness-only change: it ships ZERO non-test source (a test-tier package only).

**Date:** 2026-08-12

**Context:** the hardening work that closes the "the receiver NEVER panics on adversarial input" docstring contract — three successive changes (the digest frame, the PQ-verify, the hybrid SIGN frame) had each WIDENED that claim without a machine-driven adversarial input ever testing it. This ADR makes the project's honest-negative culture ("trust earned, not marketed") falsifiable.

## §1 — The Decision

I ship a NEW test-tier package `pkg/security/fuzz/` — the native `go test -fuzz` harness against the FOUR-way `DispatchFrame` router (pkg/mesh/digest.go:176) + the FIVE ingest-path unmarshalers under it (`attribution.UnmarshalRelayEnvelope` / `UnmarshalBatchEnvelope` / `UnmarshalHybridFrame` + `sync.UnmarshalStrataEstimator` / `UnmarshalIBLT`). The harness asserts ONE property per input: the unmarshaler / DispatchFrame call RETURNS WITHOUT PANIC (the oracle — the verdict VALUE is not asserted; the PROCESS STAYS ALIVE). The bug the fuzz catches is a PANIC: an out-of-bounds slice index, a nil-deref, an unbounded `make()` (OOM-kill), or an integer overflow that defeats a bounds guard. A native `go test -fuzz` does NOT recover — a panic FAILS the fuzz, which is the proof.

The harness is the trust anchor that makes the receiver's "NEVER panics on adversarial input" docstring contract (receiver.go HandleFrame / HandleBatchFrame / HandleHybridFrame) a FALSIFIABLE BINARY instead of a prose claim. The digest frame, the PQ-verify, and the hybrid SIGN frame each ADDED a new magic + a new unmarshaler to that SAME dispatch surface WITHOUT a machine-driven adversarial input ever testing the claim — the proof-by-prose had become a four-arm-wide claim, each arm unaudited by a machine. This change closes it.

**The frameSink REACHABILITY (the load-bearing correction).** `DispatchFrame` is EXPORTED, but its `recv frameSink` parameter's type is the UNEXPORTED interface `pkg/mesh/peer.go frameSink`. A test in a DIFFERENT package (`pkg/security/fuzz`) CANNOT name `frameSink` in its source. Go's STRUCTURAL interface typing resolves this: a type that implements the three methods `HandleFrame` / `HandleBatchFrame` / `HandleHybridFrame` each taking a `[]byte` and returning a `receive.AcceptVerdict` SATISFIES `frameSink` without naming it, and a value of that type is assignment-compatible with the unexported `recv` parameter. `nopSink` (dispatch_fuzz_test.go) is that type. The conformance is proven at COMPILE TIME — the `mesh.DispatchFrame(..., nopSink{}, ...)` call compiles IFF `nopSink` satisfies the (unexported) `frameSink`; a future change that edits `frameSink`'s method set breaks the compile here (the load-bearing reachability guard). `DigestSink` is EXPORTED (`DeliverDigest`), so `nopDigester` is a plain implementation. This is the load-bearing reachability fact — without it the dispatch fuzz could not live in `pkg/security/fuzz`.

**The ORACLE (the load-bearing property).** Each fuzz target asserts the call RETURNS WITHOUT PANIC. It does NOT assert the returned value is semantically correct (that is the round-trip tests' job — `TestEnvelope_MarshalRoundTrip` et al. already exist in `pkg/attribution`; this harness does NOT duplicate them). The fuzz is the ONLY enforcement of the no-panic contract — there is ZERO `recover()` / `defer func` in the production receive path (verified by grep; the one `recover` hit is in `envelope_test.go`, a test). NO recover guard is added to the production receive path — a recover would MASK the crash this harness is chartered to surface; the fuzz is the ONLY enforcement, and a recover would defeat it.

**The SEED CORPUS (committed, NOT git-ignored — reproducibility).** The `testdata/fuzz/FuzzX/*.txt` corpus dirs are TRACKED. The corpus is the MINIMUM per target: (a) the valid magic + a well-formed body (the happy-path seed establishing each arm's coverage); (b) a TRUNCATED magic (the first 4 bytes + NO body — the length-bomb-empty shape); (c) a length-bomb (a valid magic + a uint32 length field of `0xFFFFFFFF` — the OOM shape); (d) a 1-byte and 0-byte input (the smallest adversarial shapes). **42 committed corpus seeds across 7 targets** (Dispatch 11 + Relay 6 + Batch 4 + Hybrid 4 + Strata 5 + IBLT 6 + BugInjectControl 6). The corpus files use the EXACT on-disk format `go test -fuzz` writes (`go test fuzz v1\n[]byte("...")` with `\xNN` escapes for binary bytes — generated via `strconv.Quote` for byte-faithful round-trip), so a committed corpus file is byte-identical to what the fuzzer re-loads. The corpus is BYTE-FAITHFUL to the builders — enforced by `TestSeedCorpusMatchesBuilders` (added after a review pass caught that the original `TestSeedCorpusIsValid` tooth enforced only no-panic, NOT the builder↔corpus byte-equality the docstring claimed — the new tooth closes that enforcement gap, bug-inject-PROVEN to catch a real desync).

**THE BUG-INJECT CONTROL (`TestBugInjectControlProof` — the control-proof mold of `TestPQ_KEMClassicalControl`).** A fuzz that only feeds well-formed frames is a TAUTOLOGY; a fuzz that never catches an INJECTED panic is a no-op runner. The harness ships a deliberately-injected panic in a COPY of `UnmarshalIBLT` (a build-tagged `fuzzbuginject` target) where the bounds guard is DELETED, so on a short IBLT seed the loop reads past the wire's end → an out-of-bounds slice index panic (recoverable). The contrast IS the proof: the REAL `UnmarshalIBLT(shortSeed)` returns `ErrMalformedDigest` (NO panic — the bounds guard at iblt_wire.go:277 fires: "short bucket array: got 18 bytes, want 78 for 3 buckets"); the BUG-INJECTED copy PANICS (recovered). `TestBugInjectControlProof` is the DETERMINISTIC GREEN proof (run under `-tags fuzzbuginject`); `FuzzBugInjectControl` is the manual `-fuzz` proof (the fuzzer catches the injected panic within seconds). The bug-injected unmarshaler copy is BUILD-TAGGED `fuzzbuginject` so it is ONLY compiled when explicitly opted into — it can NEVER reach the production binary (the default build does NOT compile it; `go test ./pkg/security/fuzz/` stays GREEN).

**THE COUNTER DECISION: SKIP — no new telemetry counter ships.** A panic-firing counter (`WireFuzzPanicCaught`) needs a `recover()` in the production receive path, which the no-recover rule forbids — the recover would mask the crash. A production-firing `WireMalformedDropped` counter (on `DropMalformed`) is a DIFFERENT feature (wire-attack observability) — separate scope (touches `receiver.go` + `main.go` + `registry.go`), NOT the fuzz harness. The production receive path fires NO counter on any drop verdict today (only `SetHybridAcceptReporter` fires, on ACCEPT). A test-only counter is not a disclosure. → No counter ships. The harness is PURELY test-tier: ZERO production source touched.

## §2 — The Premise Audit (verified BEFORE code)

- **The crash surface exists + is reachable:** CONFIRMED + CORRECTED — the 4-way `DispatchFrame` (digest.go:176) + the 5 unmarshalers all exist. **The correction:** `frameSink` is UNEXPORTED (`pkg/mesh/peer.go`) but `DispatchFrame` is EXPORTED + takes `recv frameSink` — reachable from `pkg/security/fuzz` via Go's STRUCTURAL interface conformance (a type with the 3 matching methods satisfies `frameSink` WITHOUT naming it). `DigestSink` is EXPORTED. The `nopSink` conformance is proven at compile time by the `DispatchFrame(..., nopSink{}, ...)` call. The 2nd crash surface inside the relay arm — `readGateFieldsFromCapnp` (receiver.go, the v2 capnp-decode fallback) — is reached only via `HandleFrame`; the fuzz dispatches to it through the `nopSink.HandleFrame` stub, which is a NO-OP (does NOT call the real `Receiver.HandleFrame`), so the capnp path is DELIBERATELY unit-isolated out (the fuzz drives the UNMARSHAL route, NOT the full gate stack — the unit-isolation principle).
- **No recover guard in the production path:** CONFIRMED — ZERO `recover()` / `defer func` in `pkg/receive/` + `pkg/mesh/digest.go` + `pkg/attribution/` source (the single hit is `envelope_test.go`, a test). The "never panics" docstring claim is code-discipline, NOT enforced. The fuzz is the ONLY enforcement. NO recover guard is added (a recover would mask the crash).
- **The oracle = process-stays-alive:** each fuzz target asserts the call returns WITHOUT panic. Verdict value NOT asserted. `f.Fuzz(func(t *testing.T, wire []byte){ _ = DispatchFrame(wire, ..., nopSink{}, nopDigester{}) })`.
- **The committed corpus:** the `testdata/fuzz/FuzzX/*.txt` dirs are git-tracked. 42 seeds across 7 targets. The corpus generator used `strconv.Quote` for byte-faithful escapes; `TestSeedCorpusIsValid` re-runs every committed seed in corpus-only mode (no mutation) to assert no seed PANICS, + `TestSeedCorpusMatchesBuilders` re-derives the corpus from the builder aggregators + asserts byte-faithfulness (count + per-index bytes), so a hand-broken seed OR a builder mutated without regenerating the corpus fails the tooth (the desync-discipline ENFORCEMENT, not just the no-panic property).
- **The frozen core is untouched:** CONFIRMED — the merge-law/wire-schema files (`crdt.go`, `crdt_apply.go`, `schema.capnp`, `schema.capnp.go`) are unchanged. `iblt_wire.go` + `envelope.go` are conventionally stable but not part of that core → a panic found there is a fix in scope, NOT a core-file change. The harness touches ZERO production source (it is a CALLER of the unmarshalers + DispatchFrame, NOT a modifier of the CRDT/data layer).
- **The counter:** DECISION = SKIP — no new telemetry counter ships. A panic-counter needs a recover (forbidden — it would mask the crash); a malformed-drop counter is a DIFFERENT feature. See §1.
- **The 32-bit-build length-bomb residual:** DISCLOSED — `UnmarshalIBLT` (iblt_wire.go:269 `n := int(uint32)`) + `UnmarshalRelayEnvelope` (envelope.go:563 `innerLen := int(uint32)`) cast wire `uint32` length fields to `int`. On a 32-BIT build `int(uint32(0xFFFFFFFF)) == -1` → `len(wire) < negative` is FALSE → the bounds guard is DEFEATED → multi-GB `make()` → OOM-kill. On the engine's 64-bit target (arm64/x86_64, `int`==int64) the product CANNOT overflow → the guards HOLD → NO panic. The 32-bit-build length-bomb is a RESIDUAL disclosed here + in `doc.go`, NOT patched in this change (the engine targets 64-bit exclusively — Graviton arm64; a 32-bit hardening is separate work). The length-bomb seed is a COVERAGE seed on 64-bit (exercises the length-field + the bounds-guard path, returns `ErrMalformed`, NO crash), NOT a crash reproducer.

## §3 — The Teeth (4 GREEN — the corpus no-panic tooth + the corpus byte-identity tooth + the bug-inject control + the compile-time reachability guard; PLUS 6 fuzz targets executed in short-burst with NO panic found)

**The non-fuzz teeth (GREEN in the DEFAULT `go test ./pkg/security/fuzz/`):**
- `TestSeedCorpusIsValid` (seed_corpus_test.go) — walks every `testdata/fuzz/FuzzX/` corpus dir, reads each committed seed, runs it through the matching unmarshaler / DispatchFrame in corpus-only mode (NO mutation), asserts NO committed seed PANICS. A malformed seed returning an error is EXPECTED (the adversarial seeds are malformed by design); only a PANIC fails the tooth (a committed seed that crashes is a corpus defect). Counts the seeds per target so the corpus COUNT is a NUMBER: **42 total** (Dispatch 11, Relay 6, Batch 4, Hybrid 4, Strata 5, IBLT 6, BugInjectControl 6 — the last is "present + parseable" in the default build; the no-panic proof for it is `TestBugInjectControlProof` under the build tag).
- `TestSeedCorpusMatchesBuilders` (seed_corpus_test.go — added after a review pass) — the desync-discipline ENFORCEMENT tooth the docstring ORIGINALLY (wrongly) claimed `TestSeedCorpusIsValid` provided. For each target it re-derives the seed list from the builder aggregator (`seedBuilderFor` — the SAME list the target's `f.Add` consumes), reads the on-disk `testdata/fuzz/FuzzX/*.txt` corpus files in NUMERIC-index order (lexical sort mis-orders `seed-10.txt` before `seed-2.txt` — the trap the first draft fell into; the numeric sort via `parseSeedIndex` is the fix), + asserts COUNT match + per-index BYTE-EQUALITY (the Nth builder seed == the Nth on-disk file's parsed bytes). A hand-edited corpus file OR a builder mutated without regenerating the corpus FAILS the tooth. **BUG-INJECT-PROVEN** (the desync-catcher tautology-refutation, the sister of `TestBugInjectControlProof`): mutating `validIBLT` from 80 to 128 buckets (a builder edit without corpus regen) → the tooth FAILS with `FuzzUnmarshalIBLT — BYTE desync at index 0 (seed-0.txt): builder=2578 bytes vs corpus=1618 bytes` (the 128-bucket IBLT is 2578B; the committed 80-bucket corpus seed is 1618B; the magic matches but the length differs → caught); revert → PASS. Default build: 36 byte-matched seeds (the 6 default targets; `FuzzBugInjectControl` skipped with an honest log — its builder is build-tagged). `-tags fuzzbuginject`: 42 byte-matched (adds the 6 bug-inject seeds). The tooth is load-bearing, NOT a tautology.
- The COMPILE-TIME reachability guard (dispatch_fuzz_test.go) — `var _ mesh.DigestSink = nopDigester{}` + the `mesh.DispatchFrame(..., nopSink{}, ...)` call in `FuzzDispatchFrame` compile IFF `nopSink` structurally satisfies the UNEXPORTED `frameSink` + `nopDigester` satisfies `DigestSink`. A future change that edits `frameSink`'s method set breaks the compile here (the load-bearing reachability fact — §1).

**The bug-inject control (GREEN under `-tags fuzzbuginject`, OPT-IN):**
- `TestBugInjectControlProof` (bug_inject_test.go) — the control-proof mold. PROVES the harness is NOT a tautology: the REAL `UnmarshalIBLT(shortSeed)` returns `ErrMalformedDigest` (NO panic — "short bucket array: got 18 bytes, want 78 for 3 buckets"); the BUG-INJECTED copy (`bugInjectUnmarshalIBLT`, with the bounds guard DELETED) PANICS (an out-of-bounds slice index, recovered). The contrast proves a real panic IS catchable on a real input shape, so a fuzz that finds NO panic on the real unmarshalers is a genuine "no crash found" result, NOT a no-op runner. BUILD-TAGGED `fuzzbuginject` so the bug copy NEVER ships in the production binary.
- `FuzzBugInjectControl` (bug_inject_test.go, build-tagged) — the MANUAL fuzz proof: `go test -tags fuzzbuginject -fuzz=FuzzBugInjectControl -fuzztime=30s` catches the injected panic within seconds (the fuzzer mutates the short-seed shape; the deleted bounds guard yields an out-of-bounds panic). The `f.Fuzz` closure RECOVERS the panic (the bug-inject target's seeds are DELIBERATELY shaped to panic the bug copy — unlike the 6 real-unmarshaler targets which assert no-panic; the recover makes corpus-only `go test` mode pass since the panic is EXPECTED for this target; the recover is in a TEST closure behind the `fuzzbuginject` build tag, NEVER in the production receive path; the bug copy NEVER ships in the production binary).

**The 6 default fuzz targets (executed in short-burst — NO panic found on 1.6M+ mutated execs):**
- `FuzzDispatchFrame` (dispatch_fuzz_test.go, the headline) — 785,353 execs in 15s (53,335/sec), 0 new interesting inputs (the 11-seed corpus covered the branches), NO failing input → the 4-way DispatchFrame router is panic-free on 785K mutated inputs.
- `FuzzUnmarshalIBLT` (wire_unmarshal_fuzz_test.go, the highest-yield arm) — 501,769 execs in 10s (46,567/sec), 5 new interesting inputs (the fuzzer discovered 5 new coverage paths beyond the seed corpus — the length-field exploration), NO failing input → the IBLT unmarshaler is panic-free on 502K mutated inputs.
- `FuzzUnmarshalRelayEnvelope` — 302,838 execs in 6s, 4 new interesting inputs, NO failing input.
- `FuzzUnmarshalBatchEnvelope` — 323,121 execs in 6s, 3 new interesting inputs, NO failing input.
- `FuzzUnmarshalHybridFrame` — 11,132 execs in 6s (the 3404-byte hybrid header is large, so each mutated input allocates more — the 51.7× wire-cost inflation is honest), 0 new interesting, NO failing input.
- `FuzzUnmarshalStrataEstimator` — 19,202 execs in 6s, 5 new interesting inputs (the per-stratum loop exploration), NO failing input.

## §6 — The Honest Residuals + Future Work

**The honest residual (disclosed, NOT closed):** a fuzz that finds NO panic in M seconds does NOT prove no bug exists — it proves no panic for M inputs on this seed (the honest coverage-discipline line). The 72-hour PRODUCTION soak is a deployment-time run, NOT this change's gate (the `-fuzztime` NUMBER in the gate is the per-change gate; the 72-hour soak is the deployment gate). The 32-bit-build length-bomb residual (§2) is disclosed, NOT patched (the engine targets 64-bit exclusively; a 32-bit hardening is separate work).

**Future work (NOT this change):**
- **The 32-bit-build length-bomb hardening** — cast the wire `uint32` length fields to `int64` BEFORE the `int` bounds-guard comparison in `UnmarshalIBLT` + `UnmarshalRelayEnvelope` (a 2-line fix × 2 unmarshalers, touches the conventionally-stable `iblt_wire.go` + `envelope.go`; a separate hardening change's scope).
- **The production-firing `WireMalformedDropped` counter** — a `DropMalformed` disclosure counter (the wire-attack observability seam; touches `receiver.go` + `main.go` + `registry.go` — a DIFFERENT feature's scope, NOT the harness; §1).
- **The full-gate-stack fuzz** — driving the REAL `Receiver.HandleFrame` (capnp decode + Verify + the gate stack) NOT just the unmarshal route (a separate harness that needs a real `Receiver` + `Directory` + engine — NOT a no-panic property harness; the unit-isolation principle this change honors).
- **The silicon-scale fuzz soak** — the 72-hour production soak on named silicon (the deployment gate, NOT this change's CI gate).
- **The `cmd/sovereign-node` mesh peer-dial loop** (a pre-existing codebase gap) — the 2-node BINARY mesh cannot converge until that lands; the fuzz harness is single-process + the E2E USEFUL proof is the in-process stubs (the harness does NOT depend on the dial loop).
