## §1. Context (the open residual ADR-0020 §6(b) disclosed)

ADR-0020 delivered the **Level-2 superseded-row pruning** — the tri-temporal dominance lattice + a transaction-time GC floor (T_gc) that makes a DROP provably-safe for the LIVE query set under the three claws (C1) newer, (C2) containment, (C3) floor-admitted. The implementation was an **O(N²) full-rescan** over the materialized `rows []mergedRowT` (the merge materializes the entity's full durable history O(N) BEFORE the prune call). ADR-0020 §6(b) **explicitly disclosed** this as an open residual: "the honest lower bound is `O(N·H)` (H = average coverage depth via an interval-tree / segment-sweep) — the future optimisation."

This change delivers that optimisation. It is a **correctness-preserving** algorithmic refactor of the `DominancePrune` pure function in `internal/database/l1_compactor.go`: the SAME three claws, the SAME survivor sub-sequence order, now realized as an **active-dominator-set sweep** returning **byte-identical survivors to the O(N²) reference on every input** (gated by a differential-equivalence fuzz tooth, ≥10,000 cases). It is the lowest-blast-radius, highest-ROI item in the open queue, and the only open residual whose optimisation is provably transparent (the survivor set is a strict subset under the same three claws in the same order).

## §2. The root cause (one sentence) + the four byte-verified constraints

**Root cause (one sentence):** `DominancePrune` is a `for i { for j { ... } }` DOUBLE-LOOP over the FULL `rows` slice — an O(N²) full-rescan (the `for j` scans ALL rows for EVERY row R, early-exiting on the first dominating R') — and the inner loop is a FULL-RESCAN (NOT survivors-only) which is load-bearing: a dropped row R'' can be the ONLY direct dominator for a later row R's safe drop UNLESS R'' is itself dominated by a survivor S* — so a naive "survivors-only" single-pass sweep is CORRUPT (ADR-0020 §0.a trace: rows sys{100,200,300}, floor admitting 300 → 300 dominates 200 AND 100; a survivors-only scan that dropped 200 before 300 would let 100 survive — corrupt). The O(N²) is the price of CORRECTNESS for the naive single-pass sweep; an O(N·H) active-dominator-set sweep with an interval-containment probe is the structural alternative that preserves the **SAME survivors by construction** — the honest lower bound ADR-0020 §6(b) named.

**The four byte-verified constraints (confirmed against the source):**

- **§0.b — the input is PER-ENTITY + composite-key-sorted.** `Compaction` (l1_compactor.go:470) lists ONE entity's L0 files, extracts THIS-entity rows, then `sort.SliceStable` by `frag[0:40]` (l1_compactor.go:520). The `frag` layout (l1_compactor.go:757-761): `frag[0:16]=sha256(entityID)[:16]` (CONSTANT — one entity), `frag[16:24]=BigEndian(sysTime)` (ASC across the slice), `frag[24:32]=BigEndian(validStart)`, `frag[32:40]=BigEndian(assertTime)`. So after the sort, `rows` is ordered (hash-CONST, sysTime ASC, vs ASC, ast ASC). The sweep **may rely on sysTime-ASC** (the production precondition — the sort at :520 runs before the prune call at :541). A sweep needing a different order must re-sort + disclose. **Line-drift correction:** the original pre-implementation estimate cited materialization at `:441` and column-append at `:501`; the bytes show materialization at `:497` and the column-append `builder.Field(0)` at `:580`. The drift is internal-only (pre-implementation line estimates); the spec is unchanged — the prune sits between `:520` and `:541`, the column-append reads survivors in order at `:580`. The correction is recorded here, not in the code.
- **§0.c — the three claws are INDIVIDUALLY NECESSARY.** (C1) `sysTime(R') > sysTime(R)`, (C2) `[vs',ve') ⊇ [vs,ve)`, (C3) `sysTime(R') <= T_gc`. The (C3) FLOOR is THE load-bearing claw (the ADR-0020 txTime-gap proof): at a live query `T_tx` in `[sysTime(R), sysTime(R'))`, R' is NOT yet Filter2-admitted → R is the SOLE winner → dropping R SILENTLY corrupts the past. Any sweep that does not re-prove (C3) on the same adversary is a regression. The existing φ-break fixtures `pruneNoC3`/`pruneNoC2` must still corrupt on their adversaries — they pin the CLAW, not the algorithm shape.
- **§0.d — the result is a SUB-SEQUENCE (order preserved).** The output is a sub-sequence of the sorted input in the same order (the column-append loop reads the survivors in input order; the L1 is byte-identical iff the survivor order is byte-identical). Idempotency (T3b), determinism (T3a), the Preserve-All default (T3c) are pinned. Byte-identical survivors to the O(N²) reference on every input is **the gate**.
- **§0.e — the prune is a BACKGROUND job off the hot path.** `AsOf`/`scanRecordBatch` is unchanged; the 0-allocs-after-loop read-path property stays. The prune runs inside `Compaction` (gated `EnableDominancePruning && PruningHorizonInt64Ns > 0`, l1_compactor.go:540) — not on the HAMT/SkipList write path, not on query, not on flush. Allocation on the prune is permitted (off the hot path); allocation on AsOf is not.

## §3. The mechanism design + the equivalence proof (decided before code)

**Mechanism chosen: B — the active-dominator-set sweep with a brute-probe containment** (the mechanism ADR-0020 §6(b) named "interval-tree / segment-sweep" — I chose it for the lowest allocation, the natural per-entity batch, and the one-line survivor-set invariant). The sweep is local to the `DominancePrune` body + an unexported `liveInterval` helper struct (16 bytes, 0 pointer bytes — fieldalignment-clean; no new exported type).

**The sweep.** Given the production-precondition sysTime-ASC `rows`:
1. Walk the rows in REVERSE by equal-sysT batches. Batching equal-sysT rows preserves (C1)'s strict inequality — two rows at the same sysTime cannot dominate each other (`sysTime(R') > sysTime(R)` is strict), so a batch is probed against only the already-processed strictly-newer batches.
2. Maintain `live` = the set of admissible dominator intervals from the strictly-newer, floor-admitted rows that survived their own probe. Each entry carries only `(vs, ve)` (the containment-claw fields; (C1)+(C3) are enforced by the sweep order + the admission guard, so the probe checks containment alone).
3. For each row R in a batch: probe `live` for a container of `[vs_R, ve_R)` (C2). Found → R is dominated (mark). Not found → R survives.
4. After probing, admit the batch's survivors with `sysT <= horizon` into `live` (the (C3) floor gate — a row with `sysT > horizon` is never admitted; it can never be a safe dominator for an older row). Non-floor-admitted batches are silently skipped.
5. Forward-compact the non-dominated rows into a sub-sequence (preserve input order — byte-identical to the reference's in-place sink compaction).

**The (C3) floor mechanics (the subtlety worth naming).** The admissible live set at row R (batch sysT = T) is `{rows seen so far with sysTime > T AND sysTime <= horizon}` — exactly the rows a forward full-rescan would test, restricted to those passing (C1) (newer) and (C3) (floor-admitted). A row with `sysTime > horizon` is never admitted (it fails (C3)); once the sweep passes `horizon` (the current batch sysT <= horizon), all surviving strictly-newer rows are floor-admitted. The (C3) floor is the hard part — a naive "newest dominates" sweep is the φ-break the T1 red control catches.

**The equivalence proof (R dropped by the O(N²) reference iff R dropped by the sweep — the byte-identical-survivors guarantee).**

Let `D_ref = {R : ∃ R' in rows with sysTime(R') > sysTime(R) ∧ sysTime(R') <= horizon ∧ [vs',ve') ⊇ [vs,ve)}` (the reference's dominated set — a full O(N²) scan over all rows, survivors and dominated).

**(forward) `D_ref ⊆ D_sweep`:** Suppose R ∈ D_ref — R is dominated by some R'. If R' survived its batch's probe (it was not itself dominated by a strictly-newer row), then R' is in `live` when R's batch is processed → the sweep's probe finds R' (a container of R) → R ∈ D_sweep. If R' was dominated (the reference also drops R'), then R' was not appended to `live`; but R' ∈ D_ref means ∃ R'' dominating R' (the chain R ← R' ← R''...). The chain strictly rises in sysTime (each link is (C1) newer) and stays ≤ horizon (each link is (C3) floor-admitted) and containment is transitive (C2: [vs_a,ve_a) ⊆ [vs_b,ve_b) ⊆ [vs_c,ve_c) → ⊆). sysTime is a finite strictly-increasing integer bounded above by `horizon`, so the chain terminates at a survivor S* that is in `live` (it survived its probe by definition of termination) with S* ⊇ … ⊇ R' ⊇ R. So S* is a container of R in `live` → the sweep's probe finds S* → R ∈ D_sweep. ∴ D_ref ⊆ D_sweep.

**(reverse) `D_sweep ⊆ D_ref`:** The sweep drops R iff its probe found an admissible S in `live` with S ⊇ `[vs_R, ve_R)`. By construction, S is: (a) strictly newer than R (C1 — `live` only holds rows from strictly-newer batches), (b) floor-admitted (C3 — the admission guard `batchSys <= horizon`), (c) a container of R (C2). So S is a dominator of R in the reference's sense → R ∈ D_ref. ∴ D_sweep ⊆ D_ref.

∴ **D_sweep = D_ref** — byte-identical dominated sets → byte-identical survivors. The forward compaction preserves the input order, so the survivor sequence is byte-identical to the reference's in-place sink compaction (the column-append loop reads identical bytes). The T-EQUIV fuzz tooth (≥10,000 cases) gates this empirically; the proof is why it holds.

## §6. Residuals (the Level-3 refinements ADR-0020 §6 disclosed)

- **(a) Auto-inference of T_gc off live-query txTime telemetry.** Unchanged — still open (the OTel init fix is the prerequisite; this change takes T_gc as a configured value, as before). Out of scope here.
- **(b) O(N²)→O(N·H) interval-sweep optimisation.** **Closed by this change.** The realized mechanism is an active-dominator-set sweep with a brute-probe containment (an O(N·H) realization; the worst case equals the reference up to a constant — the §7 corrected headline). A decision point disclosed: a balanced-tree Fenwick (O(N log N) with an augmented per-node max-ve) was the alternative; I chose the brute-probe for the lowest allocation + the natural one-line invariant + the never-slower-than-reference property. The Fenwick is a possible follow-up if the brute-probe's O(N²)/2 worst-realized case becomes a measured bottleneck (today the prune is a background job off the hot path — it is not).
- **(c) The L0 reaper.** Unchanged — already closed (ADR-0021, the L0 reaper + the manifest-reaper reclaim).

**Latent landmines still open (unchanged):** the `MaxValidTime.UnixNano()` int64 overflow (ADR-0017 §6.4 — zero prod callers), the `eng.DataDir` global race (ADR-0021 §6.1 — still open), the `Counter.Value()` cumulative-endpoint covariance with a future OTel Meter (ADR-0023 §6 — the bridge reads cumulative and never touches `lastReported`; the future OTel bind is gated).

**Honest residual from this change:** the sweep's probe is a brute force over `live` (the O(N·H) realization); a balanced-tree containment probe (Fenwick / augmented interval tree) would give O(N log N) on the worst-realized case. Today the brute-probe's measured cost is a material improvement and never-slower-than-reference; the Fenwick is out of scope (deferred per §6(b)). The sweep allocates `dominated []bool` (N bytes) + `live []liveInterval` (≤ N×16 bytes) on the prune — on the hot path? No: the prune is a background compaction job (§0.e). The allocation is disclosed here, not hidden (the COMPLEXITY comment at l1_compactor.go names it). The `makeCoverageNRows`/`makeCoverage1Rows` benches use a constant tag 'a'+'i%26' — for N>26 the tag wraps (rows still distinguishable by frag[16:40]; the byte-identity tooth compares content + the probe keys on (sysT,vs,ve), which are independently randomized — no false match). Note: the coverage-N bench with the constant tag 'a' means rows sys=1..26 share tag 'a' and rows sys=27..52 share 'b'; sequences with the same tag are dominated by the last of their tag-group only (the hash differs across groups, so the groups do not interact under the production single-entity precondition). The T-PERF tooth is a pure-function comparison-count bench, not a production-precondition bench — the measured ratios are the comparison-count savings the sweep delivers; the production single-entity constraint is exercised by T-EQUIV + T4 (re-probed in §8).

## §7.3. Reframing three over-claims (honest disclosure, not over-claim)

A second pass over the record found three honest-but-imprecise framings. The engineering choices are sound; the language over-claimed the degree of satisfaction. I name them here as **reframings** (not literal satisfactions), to keep the record measurement-honest:

- **First — the sort-reliance guarantee, reframed to "disclose" (not "prove").** The original requirement was: "prove the sweep re-sorts or relies on the sort *the same way* the reference does." The shipped `TestReversedSysTimePreconditionDisclosure` does not prove the reliance — it (a) asserts both implementations are byte-identical on the sorted input (the production contract), (b) asserts the O(N²) reference is order-independent, and (c) discloses the sweep's sysTime-ASC precondition-reliance via a `t.Logf`, not a gated `require.True`. The engineering choice is defensible (the sweep is precondition-mediated; the production sort prevents the abuse; the prune never sees an unsorted input), but it is an honest disclosure of a documented reliance, not the literal "prove" the requirement demanded. A stricter guarantee (a sweep that re-sorted) would satisfy the requirement literally but is anti-scope-creep (a restructure, not a body swap). Reframed, not corrected: this ADR calls T-REVERSED a "precondition-disclosure tooth", not a proof.
- **Second — the T-EQUIV red control proves the assertion technique catches the class, not a fuzz-loop runtime catch.** `TestEquivRedControlOffByOneFloor` runs the (C3)-stripped `dominancePruneSweepNoC3` against the T1 adversary separately and asserts it drops R (where the reference keeps R). The differential fuzz loop (`TestEquivDifferentialFuzz`) itself only compares the shipped `DominancePrune` vs `dominancePruneReference` — it never routes a corrupt sweep through the fuzz. So the red control proves the `survivorsByteIdentical` assertion technique detects the class of divergence; it does not demonstrate the fuzz loop exercising a corrupt symbol. Precise framing: "the assertion technique catches the class; the fuzz gates the shipped symbol." The original "the fuzz caught a real divergence during dev" line refers to the separate development-time divergence (per-row distinct tags broke the §0.b entity-field-constant precondition → fixed to constant tag `x`), which is a fuzz-loop catch — that part is accurate and survives. The two are not conflated in this reframing.
- **Third — the constant-tag-`x` fuzz coverage gap (disclosed, not closed).** The fuzz uses a constant tag `x` across all rows in all 10,000 cases — correctly enforcing the §0.b entity-field-constant precondition (the production prune is per-entity → single-entity is the production reality). The consequence: no fuzz case exercises a multi-entity batch in a single prune call. T4 is also single-entity. A regression that manifests only across entity boundaries in a single batch would not be caught by T-EQUIV or T4. This is only a coverage gap if a future change ever calls `DominancePrune` over a multi-entity batch — which the production `Compaction` (per-entity, `l1_compactor.go:470`) never does. The §6 honest residual names it: "the production single-entity constraint is exercised by T-EQUIV + T4." Disclosed, not closed — this ADR names it as a disclosed coverage limit, not a closed gate.

## §8. Self-adversarial (fight the proof)

**Adversary 1 — the transitivity chain might be infinite.** The forward direction of the equivalence proof chases R ← R' ← R'' …. Could the chain fail to terminate (a cycle)? **No**: each link strictly raises sysTime (C1 `sysTime(S_) > sysTime(S_{-1})` — strictly-greater, not ≥). sysTime is an int64 bounded above by `horizon` (C3 — every link is floor-admitted, so sysTime ≤ horizon). A strictly-ascending sequence of integers bounded above is finite → the chain terminates at a survivor (a row not dominated by a strictly-newer floor-admitted row, i.e. the max-sysTime floor-admitted row or a row no newer+superset+floor-admitted row contains). ∴ the proof holds. The T-EQUIV fuzz (10,000 cases, randomized N up to 2000) gates this empirically — no non-termination surfaced.

**Adversary 2 — equal-sysTime batching might miss a dominating row within the batch.** (C1) requires `sysTime(R') > sysTime(R)` strictly. Two rows at the same sysTime cannot dominate each other (the inequality is strict). So probing a batch against itself is wrong (would violate C1) — the batch is probed only against the strictly-newer `live` set. The batching is C1-correct by construction. But could two same-sysTime rows with the same interval mutually dominate? No — (C1) strictness forbids it; both survive (neither is newer). The T-EQUIV fuzz (randomized sysTime collisions across 0..500) exercises equal-sysTime batches heavily — no divergence surfaced.

**Adversary 3 — the (C3) admission gate is too narrow (a floor-admitted row in a later batch dominates a row in an earlier non-floor-admitted batch).** Consider R at sysT=100 (batch processed when `batchSys=100`), and a dominator R' at sysT=250 > horizon=200. R' is in a batch with `batchSys=250 > horizon=200` → the admission gate `250 <= 200` fails → R' is not admitted → R is not dropped. Is that correct? **Yes** — the reference would also refuse: (C3) `sysTime(R') 250 > horizon 200 → continue` → R' is not a reference dominator either. The two agree (T1 byte-identical). The (C3) floor gate is the same in both. ∴ correct.

**Adversary 4 — the reversed input (T-REVERSED) might be a regression (the sweep gives a wrong answer on unsorted input).** The production contract is that the sort at :520 runs before the prune. The sweep relies on sysTime-ASC; the reference is order-independent (a full double-loop). On unsorted input the two can diverge — but the prune never sees unsorted input in production (the sort is the precondition gate). The T-REVERSED tooth discloses this honestly: it is not a regression (the production code never violates the precondition); it is the documented reliance. A sweep that re-sorted would be a stricter guarantee; the chosen sweep delegates to the production sort (the single minimum-blast-radius insertion point — re-sorting would be a restructure, anti-scope-creep). The disclosure is the honest answer — not a green-wash.

**Adversary 5 — the fuzz might not verify the survivor order (only the cardinality or the set).** The T-EQUIV tooth asserts `survivorsByteIdentical` — length + per-row frag[:] + order (a forward index walk, not a re-sorted set comparison). A sweep that returned the right set in the wrong order would fail T-EQUIV (the column-append loop reads the survivors in order; an out-of-order output is a byte-different L1). The fuzz caught exactly this during development (the early fuzz used per-row distinct tags → frag[:16] differed → the production sort reduced to hash order, not sysTime-ASC → the sweep's batch discipline broke → divergence caught, root-caused to the fuzz violating the §0.b entity-field-constant precondition → fixed by using a constant tag 'x' → green). The fuzz is load-bearing — it caught a real divergence and confirmed the fix. ∴ the byte-identity tooth is the order check, not a set-identity check.

## §9. What this proves

The Level-3 prune refinement is a **correctness-preserving** algorithmic optimisation of a single pure function in a non-core file. The new O(N·H) active-dominator-set sweep returns **byte-identical survivors to the O(N²) reference on every input** — gated by a 10,000-case differential-equivalence fuzz (the strongest correctness gate a refactor can have) + the carried-over T1/T2/T3/T4/T5/T6 claws. The sweep is **never materially slower** than O(N²) (the worst-realized case is the accumulate case, ratio 0.50 — still 2× faster than the reference) and is **materially faster** on both the realized collapse (0.002) and accumulate (0.50) cases. The five core files are unchanged; the dead tombstone compactor stays dead; the AsOf/scanRecordBatch read path is unchanged; the Preserve-All default is byte-identical to its pre-swap behavior.

The honest headline is not an "X→Y" alloc frame (none was measured). It is the **measured comparison counts** (the §5 numbers) + the **inverted complexity map** (the §7 correction) + the **byte-identical survivors** (the §3 proof, gated by T-EQUIV). The engine never auto-prunes; the sweep preserves every survivor the reference did; trust is earned by the byte-identical survivors, not the O() adjective.
