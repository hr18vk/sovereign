# ADR-0030: The Manifest-Channel Download Skip — the Transitively-Safe Elimination on the Second Download Channel

**Status:** ACCEPTED (2026-08-09). This change adds a read-path elimination plus a disclosure counter; it does not touch the single-writer root-equality qualifier or the core `crdt.go`.

**Closes:** the manifest channel of the durable AsOf/Range unbounded-download residual ADR-0017 §6 named (the second claw, after ADR-0029 closed the L0/L1 file channel). The standing open item "wire Seek into `scanWindowRecordBatch`" is refuted again: `scanWindowRecordBatch` takes `arrow.Record`, not a SkipList, so the wiring is a no-op; the genuine target is the download count, not the row scan.

**Enforced by:** `internal/database/manifest_download_skip_test.go` (10 teeth — 8 green + 2 RED controls), `pkg/durability/manifest_download_skip_test.go` (3 real-`*LocalFS` route teeth), `internal/telemetry/manifest_skip_counter_test.go` (2 counter-registry teeth), `pkg/metrics/bridge_manifest_skip_test.go` (1 bridge tooth). 15 teeth across 4 packages, plus 4 updated count-assertion teeth from the earlier counter additions.

---

## §1. Context (the named residual; ADR-0029 §6 carried the file channel, ADR-0017 §6 named the unbounded download)

ADR-0017 §6.1 named the durable read path's unbounded-download residual: `AsOf` + `Range` are O(L0-files) per query because they download and decode every L0/L1 Arrow file under the entity's prefix. ADR-0029 closed the file channel: a file whose filename-encoded `FirstSysTimeNs` (the file's MIN sysTime, written into the filename by the flush) exceeds the query's txTime is transitively safe to skip — every row in it fails Filter2 (`sysTime <= txTime`), so there are zero qualifying rows, and skipping preserves the answer byte-identically while cutting the download.

This ADR closes the **manifest channel** — the second download the read path pays per query. `loadSupersededL0Keys` (query.go) lists, downloads, and `ParseManifest`-decodes every compaction manifest under the entity's `compaction/{hex8}/` prefix per query to mark L0 keys superseded before the tail cap (so the tail does not re-scan rows already merged into an L1). The manifest's filename-encoded `firstSys` is the L1's MIN sysTime — the same field the file channel skips on (`manifestKeyFor` + `l1KeyFor` share `firstSysT`, l1_compactor.go:736-737/793-794). The tautology (§0.e): when `manifest.firstSys > txTime` (strict `>`, the ADR-0029 boundary), the L1 the manifest points at is file-skipped (the ADR-0029 scan loop) and every L0 the manifest lists is file-skipped (its `firstSys >= manifest.firstSys > txTime`), so skipping the manifest download leaves the superseded set intersecting only files the scan loop skips anyway. The tailKeys and the dominant are byte-identical for the query's visible rows, and a manifest download (plus the `ParseManifest` `strings.Split` alloc) is cut.

The bound is strict (`>`): a manifest at `firstSys == txTime` points at an L1 whose first row at `sysTime == txTime` passes Filter2 (`<=`), so that L1 might qualify and its listed L0s might carry visible rows — do not skip the manifest (the §1.c boundary the ADR-0029 file-skip tooth pins, re-applied here on the manifest channel).

## §2. The root cause (one sentence) + the byte-verified constraints

**Root cause (one sentence):** the manifest channel paid an unbounded per-query download (`loadSupersededL0Keys` downloaded every manifest) even when the manifest's filename already proved it points at an L1 carrying zero rows visible at the query's txTime — the same transitively-safe elimination applied to the file channel was never extended to the manifest channel.

The byte-verified constraints (the premise audit, before code):

- **§0.a — the parser was never `.arrow`-specific (M1, load-bearing).** `parseFirstSysFromKey` was authored over the `.arrow` grammar, but the grammar is shape-based, not tier-based: `LastIndexByte('/')` finds the last `/`, `LastIndexByte('.')` finds the dot in the tail, `ParseInt` base-10 parses the decimal slice between them. The `.manifest` tail (`{firstSys}.manifest`) has the same shape — the dot is the dot, the decimal is the decimal. A standalone probe (gated as `TestManifestParser`) byte-verifies `ok=true` on `.manifest` keys with the exact int64. The earlier prose denying it ("Manifests carry `.manifest` — not parsed by this helper") was a documentation error: the grammar never excluded `.manifest`; the helper always parsed it. This change uses the property and corrects the docstring; it does not add a `.manifest` special case.

- **§0.b — the manifest and the L1 share `firstSys` (the byte-identity the tautology leverages).** `manifestKeyFor(hash8, firstSysTimeNs)` (l1_compactor.go:957) and `l1KeyFor(hash8, firstSysTimeNs)` (l1_compactor.go:943) both take the same `firstSysTimeNs` (l1_compactor.go:736 `firstSysT = rows[0].sysT` — the oldest merged row's sysTime; :737 writes the L1 key; :793-794 write the manifest key). So `manifest.firstSys == L1.firstSys` byte-identically — the tautology's step 1 (the manifest points at an L1 the file skip already skips when `firstSys > txTime`) holds by construction.

- **§0.c — `DefaultCompactionConfig()` is Preserve-All (M2's backstop).** `EnableDominancePruning: false` (l1_compactor.go:108) — the compaction preserves every merged row in the L1. So the L1 carries the same rows the manifest's listed L0s carried (the merge is concatenate + sort, no prune). This is the backstop that keeps the dominant byte-identical under a `>=` bug (§3 M2): the L1 is scanned via `l1Keys` regardless of the manifest skip, and it carries the rows.

- **§0.d — the manifest and file skips are the same elimination on two channels (M3).** Both bound the same field (`firstSys > txTime`) on the same query (`txTime` from the `AsOf`/`Range` entry). A separate `EnableManifestSkip` flag would let an operator disable one channel while leaving the other on — a non-uniformity with no production rationale. The change reuses the existing `EnableFirstSysSkip` flag (the DefaultResolverConfig opt-out contract from ADR-0029) for both channels.

- **§0.e — the tautology (the step chain, transitively safe).** For a query at txTime `T` and a manifest `M` with filename `min(M)`: (1) `min(M) > T` implies the L1 `M` points at is file-skipped (the `l1Keys` loop); (2) every L0 `M` lists has `firstSys >= min(M) > T`, so every listed L0 is file-skipped (the `l0Keys` loop); (3) a manifest whose L1 and listed L0s are all file-skipped intersects the query's visible rows at zero files, so skipping `M`'s download leaves the superseded set intersected with the visible files unchanged, and the tailKeys and the dominant are byte-identical; (4) the skip cuts the manifest download (plus the `ParseManifest` alloc). The tautology is a tautology (a manifest is skipped iff its entire reachable set is absent from the visible answer); the bound is the strict `>` (the `firstSys == txTime` boundary points at an L1 whose first row qualifies — do not skip).

## §3. The mechanism design + the load-bearing `>=` finding (decided before code, per §1)

The skip is one guarded `continue` in `loadSupersededL0Keys` (query.go): after listing the manifest keys, before downloading each manifest, `parseFirstSysFromKey(manifestKey)`; if `ok && firstSys > txTimeNs`, increment `QueryManifestSkippedFirstSys` (the disclosure) and `continue` (skip the download). The `txTimeNs` is threaded into `loadSupersededL0Keys` from the `AsOf`/`Range` entry (the same `txTimeNs := transactionTime.UnixNano()` the txTime inferrer observes and the file skip reads). The skip is opt-out (gated on `EnableFirstSysSkip`, default true — the ADR-0029 contract).

**The load-bearing finding (M2):** the initial RED-control-2 claim — "a `>=` bug on the manifest skip causes the EQUIV (dominant-answer) to diverge at every `txTime == manifest.firstSys`" — is false on the bytes for the dominant. The manifest skip affects the superseded map (which L0s leave `tailKeys`); it does not touch the L1, which `AsOf` scans via `l1Keys` (query.go:286) regardless of the manifest skip. The L1 is the compaction's Preserve-All merge of the manifest's listed L0s (§0.c), so it carries the same rows. A `>=` bug therefore leaves the boundary L0s in `tailKeys` (not removed from superseded), where the file skip does not skip them at `firstSys == txTime` (strict `>`): they are downloaded and scanned, their rows evaluate against Filter2 (pass at `sysTime == txTime`), and the dominant is the same as the no-skip path (the L1 already carries the row). **The dominant stays byte-identical under `>=`.** The `>=` bug is a performance regression (a redundant boundary-manifest download plus redundant boundary-L0 scans), not a Law-II break.

The EQUIV's `>=` catcher is therefore the **superseded-map subset assertion** (the manifest skip's removed-superseded-keys must be a subset of the file skip's removed scan-keys at the same txTime). A `>=` bug would remove a boundary L0 from superseded that the file skip does not remove at `firstSys == txTime`, and the subset assertion fails. I do not fabricate a dominant divergence the bytes do not support; the M2 finding is disclosed and the subset assertion is the honest `>=` catcher (`TestManifestEquivRedOpposite`). The opposite bug (`<=`, skip iff `firstSys <= txTime`) is caught by the subset assertion (it removes a manifest whose `base+0` L0 is not file-skippable at `txTime = base+500`); the no-op bug (never skip) is caught by the download-count tooth's "counter fires >= 1" assertion (`TestManifestEquivRedNoop`).

## §6. Future work (the honest deferred work, not this change)

- **§6.a — a zero-alloc `ParseManifest` (streaming line reader, no `strings.Split`).** This change cuts the `ParseManifest` alloc by skipping the download; it does not zero it for the non-skipped manifests. A streaming line reader is out of scope here.
- **§6.b — the upper-bound `maxSys` sidecar (discarded as orthogonal).** The candidate "wire the file MAX sysTime so a file whose entire body is before the query is skipped" bounds the opposite end (`file.max < txTime`, a file whose newest row is older than the query's txTime horizon). It requires a per-file `maxSys` the filename does not carry today (a separate manifest-sidecar change, ADR-0029 §6.a), and it is not transitively safe in the same tautological sense (a file with `max < txTime` can still carry a row a forensic query at a txTime below `max` wants — the upper bound is a heuristic, not a tautology; disclosing it as opt-in is the honest design, not this change). This change closes the lower bound on the manifest channel only.
- **§6.c — the `Seek` wiring stays dormant (the refuted premise).** `scanWindowRecordBatch` takes `arrow.Record`, not a SkipList; the Resolver holds no live MemTable; the wiring target is a no-op. The genuine first `Seek` consumer is the live cross-entity tail work (the Resolver↔MemTable seam), not the durable Arrow wiring.
- **§6.d — the reaper's manifest download is unchanged.** The reaper (`l0_reaper.go:159`) has no txTime (it verifies L1 existence across all entities, a maintenance sweep). Do not share a skip with the reaper; its manifest download is a different concern (delete-after-read safety, not query cache). The §0.b boundary: a skip tinged by txTime must not bleed into a txTime-less sweep.
