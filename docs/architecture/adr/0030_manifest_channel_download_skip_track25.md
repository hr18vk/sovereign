## §1. Context (the named residual; ADR-0029 §6 carried the FILE channel, ADR-0017 §6 named the unbounded download)

ADR-0017 §6.1 named the durable read path's unbounded-download residual: `AsOf` + `Range` are O(L0-files) per query because they DOWNLOAD + DECODE every L0/L1 Arrow file under the entity's prefix. Day-24 (ADR-0029) closed the FILE channel: a file whose filename-encoded `FirstSysTimeNs` (the file's MIN sysTime, written by the flush since Day-13) exceeds the query's txTime is transitively-safe to skip — every row in it fails Filter2 (`sysTime <= txTime`) → zero qualifying rows → skipping preserves the answer byte-identically (Law II) AND cuts the download.

Day-25 closes the **MANIFEST channel** — the SECOND download the read path pays per query. `loadSupersededL0Keys` (query.go) lists + downloads + `ParseManifest`-decodes EVERY compaction manifest under the entity's `compaction/{hex8}/` prefix per query to mark L0 keys superseded before the tail cap (so the tail does not re-scan rows already merged into an L1). The manifest's filename-encoded `firstSys` is the L1's MIN sysTime — the SAME field Day-24 skips on the file channel (`manifestKeyFor` + `l1KeyFor` share `firstSysT`, l1_compactor.go:736-737/793-794). The tautology (§0.e): when `manifest.firstSys > txTime` (STRICT `>`, the Day-24 boundary), the L1 the manifest points at is file-skipped (Day-24 scan loop) AND every L0 the manifest lists is file-skipped (its `firstSys >= manifest.firstSys > txTime`) → skipping the manifest DOWNLOAD leaves the superseded set intersecting ONLY files the scan loop skips anyway → the tailKeys + the dominant are byte-identical for the query's VISIBLE rows (Law II) AND a manifest Download (+ the `ParseManifest` `strings.Split` alloc) is cut.

The bound is STRICT (`>`): a manifest at `firstSys == txTime` points at an L1 whose first row AT `sysTime == txTime` passes Filter2 (`<=`) → that L1 MIGHT qualify → its listed L0s MIGHT carry visible rows → DO NOT skip the manifest (the §1.c boundary the Day-24 file-skip tooth pins, re-pinned here on the manifest channel).

## §2. The root cause (one sentence) + the byte-verified constraints

**Root cause (one sentence):** the manifest channel paid an unbounded per-query download (`loadSupersededL0Keys` downloaded every manifest) even when the manifest's filename ALREADY proved it points at an L1 carrying ZERO rows visible at the query's txTime — the SAME transitively-safe elimination Day-24 applied to the FILE channel was never extended to the manifest channel.

The byte-verified constraints (the §0 premise-audit, BEFORE code):

- **§0.a — the parser was NEVER `.arrow`-specific (M1, load-bearing).** `parseFirstSysFromKey` was authored Day-24 over the `.arrow` grammar, but the grammar is SHAPE-based, NOT tier-based: `LastIndexByte('/')` finds the last `/`, `LastIndexByte('.')` finds the dot in the tail, `ParseInt` base-10 parses the decimal slice between them. The `.manifest` tail (`{firstSys}.manifest`) has the SAME shape — the dot is the dot, the decimal is the decimal. A standalone probe (gated as T-MANIFEST-PARSER) byte-verifies `ok=true` on `.manifest` keys with the EXACT int64. The prior Day-24 prose denying it ("Manifests carry `.manifest` — NOT parsed by this helper") was a DOCUMENTATION ERROR: the grammar NEVER excluded `.manifest`; the helper ALWAYS parsed it. Day-25 USES the property + corrects the docstring; it does NOT add a `.manifest` special case.

- **§0.b — the manifest + the L1 SHARE `firstSys` (the byte-identity the tautology leverages).** `manifestKeyFor(hash8, firstSysTimeNs)` (l1_compactor.go:957) + `l1KeyFor(hash8, firstSysTimeNs)` (l1_compactor.go:943) both take the SAME `firstSysTimeNs` (l1_compactor.go:736 `firstSysT = rows[0].sysT` — the OLDEST merged row's sysTime; :737 writes the L1 key; :793-794 write the manifest key). So `manifest.firstSys == L1.firstSys` byte-identically — the tautology's step 1 (the manifest points at an L1 the Day-24 file-skip ALREADY skips when `firstSys > txTime`) holds BY CONSTRUCTION.

- **§0.c — `DefaultCompactionConfig()` is Preserve-All (M2's backstop).** `EnableDominancePruning: false` (l1_compactor.go:108) — the compaction PRESERVES every merged row in the L1. So the L1 carries the SAME rows the manifest's listed L0s carried (the merge = concatenate + sort, no prune). This is the backstop that keeps the dominant byte-identical under a `>=` bug (§3 M2): the L1 is scanned via `l1Keys` REGARDLESS of the manifest skip, and it carries the rows.

- **§0.d — the manifest + file skips are the SAME elimination on two channels (M3).** Both bound the SAME field (`firstSys > txTime`) on the SAME query (`txTime` from `AsOf`/`Range` entry). A separate `EnableManifestSkip` flag would let an operator disable one channel while leaving the other on — a non-uniformity with NO production rationale. Day-25 reuses the EXISTING `EnableFirstSysSkip` flag (DefaultResolverConfig opt-OUT contract, Day-24) for BOTH channels.

- **§0.e — the tautology (the §0.e step chain, transitively-safe).** For a query at txTime `T` + a manifest `M` with filename `min(M)`: (1) `min(M) > T` ⟹ the L1 `M` points at is file-skipped (Day-24, `l1Keys` loop); (2) every L0 `M` lists has `firstSys >= min(M) > T` ⟹ every listed L0 is file-skipped (Day-24, `l0Keys` loop); (3) a manifest whose L1 + listed L0s are ALL file-skipped intersects the query's VISIBLE rows at ZERO files ⟹ skipping `M`'s download leaves the superseded set `∩` the visible files UNCHANGED ⟹ the tailKeys + the dominant are byte-identical (Law II); (4) the skip CUTS the manifest Download (+ the `ParseManifest` alloc). The tautology is a TAUTOLOGY (a manifest skipped iff its entire reachable set is absent from the visible answer); the bound is the Day-24 STRICT `>` (the `firstSys == txTime` boundary points at an L1 whose first row qualifies → DO NOT skip).

## §3. The mechanism design + the load-bearing `>=` finding (decided BEFORE code, per §1)

The skip is one guarded `continue` in `loadSupersededL0Keys` (query.go): after listing the manifest keys, before downloading each manifest, `parseFirstSysFromKey(manifestKey)`; if `ok && firstSys > txTimeNs` → increment `QueryManifestSkippedFirstSys` (the disclosure) + `continue` (skip the download). The `txTimeNs` is threaded into `loadSupersededL0Keys` from the `AsOf`/`Range` entry (the SAME `txTimeNs := transactionTime.UnixNano()` the Day-22 inferrer observes + the Day-24 file-skip reads). The skip is OPT-OUT (gated on `EnableFirstSysSkip`, default true — the Day-24 contract).

**The load-bearing finding (M2 — the §0.h honesty gate, the EIGHTH dictated-premise-correction):** the prompt's RED-control-2 claim "a `>=` bug on the manifest skip causes the EQUIV (dominant-answer) to diverge at every `txTime == manifest.firstSys`" is **FALSE on the bytes for the DOMINANT**. The manifest skip affects the SUPERSEDED map (which L0s leave `tailKeys`); it does NOT touch the L1, which `AsOf` scans via `l1Keys` (query.go:286) REGARDLESS of the manifest skip. The L1 is the compaction's Preserve-All merge of the manifest's listed L0s (§0.c) → it carries the SAME rows. So a `>=` bug leaves the boundary-L0s in `tailKeys` (NOT removed from superseded), where the Day-24 FILE skip does NOT skip them at `firstSys == txTime` (STRICT `>`) → they are downloaded + scanned → their rows evaluate against Filter2 (PASS at `sysTime == txTime`) → the dominant is the SAME as the no-skip path (the L1 already carries the row). **The DOMINANT stays byte-identical under `>=`.** The `>=` bug is a PERF regression (a redundant boundary-manifest download + redundant boundary-L0 scans), NOT a Law-II break.

The EQUIV's `>=` catcher is therefore the **SUPERSEDED-MAP SUBSET ASSERTION** (the manifest skip's removed-superseded-keys ⊆ the Day-24 file-skip's removed scan-keys at the SAME txTime). A `>=` bug would remove a boundary-L0 from superseded that the file-skip does NOT remove at `firstSys == txTime` → the subset assertion FAILS. Day-25 does NOT fabricate a dominant divergence the bytes do not support; it discloses the M2 finding + uses the subset assertion as the honest `>=` catcher (T-MANIFEST-EQUIV-RED-OPPOSITE). The OPPOSITE bug (`<=`, skip iff `firstSys <= txTime`) IS caught by the subset assertion (it removes a manifest whose `base+0` L0 is NOT file-skippable at `txTime = base+500`); the NO-OP bug (never skip) IS caught by the download-count tooth's "counter fires >= 1" assertion (T-MANIFEST-EQUIV-RED-NOOP).
