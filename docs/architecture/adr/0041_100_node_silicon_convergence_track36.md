## Decision

Ship FOUR edits + the silicon infra, with THREE load-bearing corrections the premise-audit caught BEFORE code:

### Edit 0 — the IBLT heap-bomb bound (the load-bearing denominator correction)

`pkg/sync/iblt_wire.go` (NON-FROZEN — Edit 0 is the only `pkg/sync` production touch) gains a heap-bound guard in `UnmarshalIBLT`: a wire `numBuckets` exceeding `maxIBLTBuckets = maxFrameSizeBytes / unsafe.Sizeof(Bucket{})` is REJECTED with `ErrIBLTTooLarge` BEFORE the `make([]Bucket, numBuckets)` alloc path (`NewIBLTWithSeed`).

**The load-bearing premise-audit correction**: the bound's denominator is the in-memory `sizeof(Bucket) = 24` bytes (→ `maxIBLTBuckets = 699050`), NOT the on-wire `bucketWireLen = 20` bytes (→ 838860, which would let `n=838859` through and FAIL the tooth). The IBLT heap-bomb is `n=838859` (the max-through-`ReadFrame` shape: 838859×20 = 16,777,180 wire bytes ≤ the 16 MiB frame cap) → `make([]Bucket, 838859)` = 838859×24 = 20,131,616 ≈ 19.2 MiB heap (a 1.2× amplification over the wire). The `/24` bound rejects it; the `/20` bound would not. The literal `16 << 20` is DUPLICATED in `iblt_wire.go` (NOT imported from a shared const) to avoid the import cycle (`pkg/receive → pkg/sync` already; a shared const would either duplicate or cycle). The `var` (not `const`) because `unsafe.Sizeof(Bucket{})` is not a compile-time const.

Runtime-verified: `maxIBLTBuckets = 699050`, `n=838859` REJECTED, `n=80` (strataIBLTBuckets) + `n=0` ACCEPTED. The `T-LOOP-IBLT-BOUND-LOCKSTEP` tooth proves the edge: `n=699050` accepts, `n=699051` rejects (the denominator is 24, not 20 — the load-bearing fact).

**The tiered-keys decision** (the load-bearing harness-config correction): the loopback convergence oracle (chaos `MerkleRoots → eng.State().MerkleRoot` at crdt.go:1348) is documented OFF the Join hot path "for the SMALL live sets those callers observe" (crdt.go:1341).
